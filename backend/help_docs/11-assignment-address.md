# 任务分配与小区匹配

## 地址匹配状态

平台保留任务原始地址，并使用本地规则生成小区和社区建议：

- **自动匹配**：唯一、有效且没有街道或社区冲突，可直接参与分配；它不是人工确认，但有权限的人员仍可在“确认地址”页面纠正。
- **已确认**：管理员纠正后的最终结果，优先级最高。
- **待确认**：多个小区接近，需要继续标注；当前社区明确时仍可分配核查人。
- **地址冲突**：街道、社区或小区归属相互矛盾。
- **待标注**：信息不足或内容明显不是住宅地址。

系统不会因为地址格式不标准就直接判错，也不会覆盖原始地址。错别字、简称、栋幢写法等只用于生成建议。

候选去重后如果只有一个有效小区，平台会直接显示为“自动匹配”，不再要求重复确认。只有确实存在两个不同小区且结果接近时，才显示“多候选待确认”。

## 在确认地址工作台连续核对

流口任务仅在小区名称旁显示一个状态标签。点击“自动匹配”“已确认”“待确认”“地址冲突”“待标注”或“无匹配小区”，会直接打开这条任务，不受工作台默认待处理筛选限制。原任务有未保存修改时，请等待保存完成；保存失败可返回重试或明确放弃，不能直接丢弃输入。

桌面左侧选择任务，右侧对照原始地址、现住址、任务社区及当前小区。小窗口和手机使用队列、核对两级视图，通过“返回任务队列”切换。原始地址只读。

1. 推荐项可直接选中；没有推荐时，仍可搜索当前正式社区全部启用小区。选中不会立即保存。
2. 队列核对默认“确认并下一条”，也可“确认并停留”。通过任务标签进入时默认停留，防止误跳到其他任务。
3. 成功保存才会更新队列并进入下一条。通过“上一条已保存 · 查看”或“最近处理”回看；回看后可返回刚才正在核对的任务。
4. 最近处理只在本次页面会话保留最多 20 条定位。刷新后通过“已确认”“无匹配小区”或“全部结果”筛选并搜索找回，不依赖最近处理列表。
5. 保存失败保留选择。出现版本冲突时，先“重新核对最新版本”，对照新的地址、社区与保留的选择，确认后再提交。
6. 无权操作时仍可查看任务及选项，请联系有任务管理权限的组长或上级岗位；社区冲突请联系基础管控或管理员。页面只显示当前账号可以执行的操作。

跨社区候选单独显示。具备权限的人员可以“修正到此社区并重新匹配”，提交前核对原社区、目标社区及对任务归属的影响，再检查新的小区结果。

## 确实没有合适小区

选择“无匹配小区”，并从以下原因中选择一项：地址信息不足、地址不属于现有小区、小区库缺失、不在当前社区、其他待核实。不要在原因中填写人员资料或完整地址。

这是已经人工核对的结论，与算法还没找到结果的“待标注”不同。它不会创建“未知小区”，不会修改原始地址、社区、核查结果或自动解除核查人。当前正式社区明确、来源唯一时仍可分配给该社区的在岗核查人；补齐信息后可重新标注具体小区。

地址和社区未变化时，规则重算保留人工结论；原始地址、现住址或社区变化后需要重新核对。与已有精确地址记忆冲突时，暂停该记忆自动复用，历史人工记录保留。

## 人工确认会怎样被记住

管理员人工纠正小区后，平台会记住“同一规范化地址 + 同一社区”的确认结果。以后遇到完全相同的地址，可以自动复用该结果：

- 不会把确认结果模糊套用到只是看起来相似的其他地址；
- 不会跨社区复用；
- 两次人工确认互相矛盾时，系统停止自动复用并重新交给人工处理；
- 原始地址仍然保留，反馈记忆中不另存地址正文。

这种能力属于安全的规则记忆，不是平台在操作过程中即时训练深度学习模型。人工确认记录可以在以后经过脱敏评估后，作为地址模型的离线训练和阈值校准样本。

## 按小区筛选并分配

分配工作台会按窗口内可用宽度自动排列多列任务卡片；手机等窄屏显示单列。任务按地址顺序从左到右、从上到下排列，可点击选择，电脑端也可拖动跨列选择。缩放窗口后，已选任务仍保留；长地址会换行显示。

1. 进入分配工作台。
2. 先选择社区，可选小区进一步缩小范围；小区不是分配的必填条件。
3. 可继续选择匹配状态或输入地址关键词。
4. 勾选任务后选择单人分配或平均分配。
5. 查看成功、跳过和失败明细。

当前正式社区明确、来源唯一且未完成、未分配的任务可以进入单人或平均分配，包括待确认和无匹配小区任务。核查人必须是任务社区的在岗人员；未知社区、来源异常、已完成或已有核查人的任务仍会拒绝或跳过。小区标注保留独立处理，不会因分配而变成人工确认。

## 取消错误分配

如果误用平均分配造成数据混乱，具备权限的人员可以使用“取消已分配数据”恢复未分配状态，再按社区、小区重新筛选和分配。取消前应确认任务尚未被核查，避免覆盖已经产生的有效工作。

## 所内移交

结果为“移交（所内）”时，基础管控可选择目标正式社区：

- 目标社区只有一名在岗组长时，系统自动选择该组长。
- 有多名组长时必须明确选择。
- 没有在岗组长时不能提交，应先维护人员配置。

任务会进入接手组长的当前待办，但在线汇总中的有效工作量仍归第一次核查该任务的人员。
