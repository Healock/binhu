# 无法核实与两级研判

六类流口业务的“无法核实”必须进入统一研判流程；疑似未注销模型三不参与该流程。

## 流程

```text
无法核实
→ 初步待研判
→ 初步延时复核或深度待研判
→ 深度延时复核或最终无法核实
→ 当前业务导出归档
```

## 初步研判

- **发现新线索**：必须填写意见，系统把截止日期顺延 2 个完整自然日。
- **未发现新线索**：必须填写意见，立即进入深度待研判。

## 深度研判

- **发现新线索**：必须填写意见，系统把截止日期顺延 1 个完整自然日。
- **未发现新线索**：必须填写意见，立即形成最终无法核实。

截止日当天不自动升级，只有业务日期晚于截止日才流转。延时期间网格员如果已经核实，应立即把核查结果改为已登记、离苏、无需登记等正式结果。

## 导出和回导研判文件

初步待研判、深度待研判可以按当前筛选和排序导出统一工作簿。基础管控只填写“本次研判结果”和“研判意见”后回导。空白行会跳过；阶段、版本或来源已经变化的行会明确失败，不会覆盖最新数据。

## 最终无法核实

只有深度研判结束后形成的最终无法核实，才可在对应业务列表中预览并导出归档。待研判文件导出仅用于离线研判，不会删除或归档任务。


研判工作表的参考信息只读，填写区仅包含“本次研判结果”和“研判意见”。结果只能选择“发现新线索”或“未发现新线索”；已核实、已见底必须由后续流口指令核查中的网格员确认。初步阶段未发现新线索进入深度待研判，深度阶段未发现新线索进入最终无法核实；发现新线索分别进入两天或一天延时核查。旧成功/失败文件仍可兼容导入，并会标记旧格式。空白结果跳过，缺少研判意见逐行失败。
