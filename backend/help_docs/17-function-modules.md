# 功能模块与单位权限

## 访问规则

页面是否可用由模块归属和原有功能权限共同决定，两者是 AND 关系。模块通过 `_function_module_units` 绑定一个或多个真实部门 ID；人员所属部门会沿部门树向上追溯，命中任一绑定部门即可访问。公共模块面向所有登录账号。管理员和超级管理员可以跨部门查看，但仍受页面原有功能权限限制。`department_type` 只描述部门级别，不用于模块授权。

桌面侧栏、手机导航和直接页面访问使用启动接口返回的可用模块集合。隐藏导航只是界面行为，后端接口仍会检查模块归属和原有权限。

## 看不到功能时

常见原因有三类：模块绑定部门与账号部门层级不相交、权限组没有授予该页面所需权限，或模块当前已停用。请联系管理员核对人员部门归属、模块部门绑定、权限组和启用状态；调整后重新登录或刷新页面。

模块定义和部门绑定变更会保存版本快照，便于管理员核对模块归属变化记录。

## 上线前检查

本功能依赖 PR-A0 的部门维护能力。上线前必须先建立社区警务队、片区、社区、综合指挥室等部门层级，并完成在用人员的 `_grid_member_department_links` 回填；然后将社区警务队一次性绑定全部社区业务模块，再启用门禁。PR-A 不负责创建部门或迁移人员，未完成前不得直接合并上线，否则未命中部门树的账号会得到 403。

## 上线前检查

启用社区警务门禁前，管理员必须先为所有在用账号补齐社区部门关联，并逐一验证在线查询、任务台和辖区档案等接口。部门关联缺失时系统会拒绝社区警务模块访问，这是保护数据边界的故障关闭行为，不会在数据库异常或关系缺失时自动放行。模块管理入口位于“系统设置—功能模块”，只有具备 `module.access.manage` 的管理员可以修改。

当前在线查询、流口任务、汇总、档案和场所码等社区业务暂共用 `community_police` 模块；工单中心单独使用 `workflow` 模块，平台管理使用 `platform_admin`。后续出现差异化单位需求时，再增加独立模块，不在页面中用隐藏菜单代替后端门禁。
