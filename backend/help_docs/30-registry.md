# 辖区档案

辖区档案用于维护房屋、人员和机构等基础资料。不同岗位只能查看或维护权限范围内的数据。

## 房屋档案

房屋列表支持按社区、小区、地址、类型和匹配状态筛选。常用操作包括：

- 新建或编辑房屋；
- 维护标准地址、楼栋和房号；
- 关联小区；
- 查看最近走访日期和最近星级评定；
- 进入详情查看历史走访、次数和具体记录；
- 按当前筛选和排序导出。

标准地址不要求固定格式。系统会保留原始内容并使用结构化特征辅助匹配，不应为了匹配而篡改真实地址。

房屋页的“注销状态”来自户号表，支持筛选已注销、未注销和未知，列表和导出使用相同条件。平台不再展示房屋启用/停用操作；历史停用记录也可查看，不把停用推断为注销。户号表的“注销状态”“房屋状态”“房屋登记状态”或“状态”列会在预览及确认导入时保存；数字代码和无法识别的值显示未知，不猜测代码含义。缺少状态列的新记录为未知，更新已有档案时保留原来源状态；存在状态列但内容为空或无法识别时更新为未知。

旧版导入没有保存该列，历史房屋因此可能全部显示未知。需重新取得包含状态列的户号表，预览并确认导入后才能筛选。若同一文件因已导入被拦截，请将原工作簿另存为新的 XLSX 再上传；不要修改业务内容来绕过重复保护。缺少来源证据时不会用走访注销人数或平台停用状态补写。

## 分组户号表导入

内网单次导出有条数上限时，可以分别按“个人租赁、单位租赁、自购房屋、借住、其他”与“是否注销：是、否”查询，形成最多十份 XLSX。先记录每组查询总数，确认各组没有超过内网导出上限，并核对各组总数等于同一时间、同一范围下的全部查询总数。分类为空或不在这五种类型中的记录需要另行取得，不能因为已经有十份文件就认定全量完整。

在辖区档案的数据导入页一次选择多份户号表，每批最多十份、总大小不超过 50MB、总行数不超过 100000。逐文件选择其查询住房类型和注销状态，并填写内网查询总数。选择“按表内类型/状态”时只使用文件内容；选择已注销或未注销时，缺少或空白的状态列使用这次明确声明的查询条件，声明及原值一同保留。文件已有状态与声明冲突或无法识别时拒绝整批预览；住房类型与声明不符、实际行数和查询总数不一致时也拒绝。空分组可以不上传；只有表头的空文件会记录为零条。

点击“预览户号表”，核对每个文件的实际行数、唯一户号、缺少户号、相同重复行，以及来源和可导入记录各自的已注销、未注销和未知数量。预览的可导入数量仍需在确认时核对正式社区和现有档案，不能当作已经入库。重复导出且同社区同户号所有内容一致时只导入一个代表记录，来源行仍保留；内容、地址或注销状态不同的记录进入问题核查，不按上传顺序覆盖。不同户号允许共享地址，各自保存注销状态；跨社区同地址也不会仅因地址相同成为问题。没有户号时，同社区同地址的多条记录仍需人工核对。问题数量按来源记录去重，不重复累计同一行的多个原因。唯一户号数、来源行数和最终可导入档案数是不同指标，不能互相替代。

确认时先按正式社区及户号核对已有档案，不因同地址存在其他户号而覆盖其档案或注销状态。相同户号地址变化、同户号对应多份档案、缺少户号且地址对应多份档案，以及社区别名归一后重复的户号来源都会进入问题核查。管理员应核对原文件、社区配置和现有房屋档案；地址确需调整时维护原房屋地址，再取得新的 XLSX 重新预览。不通过随意更改户号或忽略问题强行导入。仅有地址证据、无法区分户号的关联仍需核对，不会自动选择其中一户。

后端修补会重新判定旧预览和部分导入批次中的重复地址问题，旧问题保留为已替代历史，真实户号冲突、社区无法对应及现有档案冲突仍待核查。发布后重新点击“预览户号表”取得最新数字，不需要修改文件或另存工作簿；已导入档案、来源关联和人工决定不自动修改，也不自动补导入正式房屋。文件预览的问题数量与确认时发现的社区、已有档案问题属于不同阶段，最终待核查数量可能大于文件预览数量。

核对无误后点击“确认导入正常数据”，所有文件属于同一导入批次并复用一次确认事务，问题数据留在核查清单。没有出现在本批文件中的已有房屋不删除、不改为注销。重复提交相同文件组合及查询状态会复用批次；更改文件选择或查询条件后必须重新预览。源表中的“是/否”分别对应已注销/未注销；“个人租赁/单位租赁”按平台出租房类型保存，原始类型仍保留在来源资料。

确认结果显示本次新增、更新和待核查数量。部分导入批次再次确认只处理尚未成功挂载的来源行，已成功的记录不会重复写入。档案已有更晚创建且成功导入的批次时，旧批次不能覆盖它，需取得最新文件重新预览。批次先后只是防止旧预览倒灌，不代表已经证明源数据的业务时间；仍需管理员确认新上传文件确实是最新来源。

点击“最近走访日期”表头的筛选图标，在弹窗中选择“全部走访情况”“有走访记录”或“从未走访”，下方保留日期范围选择。从未走访表示平台全部已获取的历史走访中，没有可通过同社区、房屋当前地址、启用别名或历史地址精确关联的记录，不等于所选日期内未走访。选择从未走访会清空并禁用日期与星级条件；点击弹窗“清空”会同时清除走访情况和日期，之后可重新选择。表头图标在存在走访情况或日期条件时高亮。列表总数、分页和导出复用同一筛选。上游尚未获取到平台的走访不会参与判断。

读取房东责任告知书时，平台会将本次完整只读来源与当前本地告知书进行对比，预览中同时显示新增、更新、未变化、来源未再出现和需核查数量，并显示读取后的责任状态预计总数。确认完整快照后，当前记录与问题以本次全民防数据为准；旧告知书及旧问题保留为历史，不再累计到当前状态，旧问题可按“已被新快照替代”查看。

同社区同地址内容完全一致的来源记录只挂载一个当前代表项。有明确且可比较的来源更新时间时，采用最新版本；不同内容无法判断先后时仍进入核对，不按分页顺序、记录编号或签署时间猜测。未签订且没有签署类型的记录显示“未签订”，本身不会产生重复或冲突问题。未匹配出租房等真实异常仍进入核查。外部读取失败、中断、空结果或本所记录缺少必要字段时保留当前状态；旧预览不能覆盖更新的已确认快照，需要重新读取。

## 小区标注工作簿

有房屋维护权限的管理员可在房屋档案中按当前筛选与排序点击“导出小区标注”。导出完整筛选结果，最多 10000 套，超过时请按社区拆分；包含四张表：房屋标注、小区地址库、候选小区和标注说明。小区地址库附带权限范围内的启用小区名称、所属社区、详细地址、别名与类型，Agent 可按小区 ID 查找，不按行号或名称猜测关联。文件仅保留地址匹配所需信息，不含人员、房东姓名、身份证、电话及走访正文；交给外部 Agent 时仍须遵守地址资料的授权范围。

外部 Agent 只填写 `decision`、`annotated_small_community_id`、`annotation_reason` 三列：

- 明确找到唯一小区：填 `match`、小区地址库中的 `id`，并填写标注依据。
- 无法确定、存在冲突或小区库缺失：填 `review` 并填写原因，等待管理员处理。
- 无需处理：填 `skip` 或保持空白。

保留工作表、表头、房屋 ID、原始地址、社区、版本和签名列，由原导出账号点击“回导小区标注”，选择工作簿预览。预览不会修改档案；异常行显示拒绝原因，版本、权限、社区、地址或小区配置已变化时须重新导出。已人工确认的小区替换不会默认勾选，应逐条核对后选择。点击“确认所选”并再次确认后才应用，最多每 200 条一批；失败停止后续批次，已确认记录保留，需重新预览后处理余下记录。

Agent 标注只提供建议，不能绕过社区一致性、小区启用状态、权限或管理员确认，也不会修改房屋原始地址和社区。房屋的注销状态不阻止确认其所属小区。标注表中的 `household_status` 为注销状态，`status` 仅为历史兼容原始列，不代表注销状态，两列均不得修改。`review` 与跳过记录保持当前关联，不能借回导新建小区或批量清空人工确认。

## 人员档案

人员可以与房屋、标签、联系方式和历史业务记录关联。搜索不到人员时，先核对姓名、身份证摘要、社区和档案关联是否完整；不要重复新建同一人员。

## 机构档案

机构资料用于记录辖区内相关单位。维护时应使用规范名称和真实有效状态，避免把临时任务标题当成机构。

## 标签

标签用于描述人员或房屋的业务属性，例如“自购自住”。标签不是核查结果，不能代替任务流程中的正式状态。
