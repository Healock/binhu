# 二维码管理

二维码管理包含“场所登记码”和“饮酒报备码”两个页签。平台本地数据库是场所、登记记录和报备记录的唯一正式业务来源；公开页面由云端接收服务提供，信息加密暂存后由滨湖服务器主动拉回，云端不是业务主库。

## 创建场所码

1. 进入“二维码管理”的“场所登记码”页签。
2. 填写场所名称、类型、地址和所属社区。
3. 保存后生成二维码。
4. 下载或展示二维码，使用手机扫码验证公开页面。

正式切换前仍使用平台本地入口。云端同步和主动拉取只有在候选环境、单场所闭环和分批验收全部通过后才会启用，用户不需要自行修改配置。

## 二维码和访问链接

二维码图片由平台接口提供，网页端和桌面客户端使用同一资源地址。若图片不显示：

1. 先尝试打开二维码详情或刷新。
2. 检查当前客户端网络和登录状态。
3. 确认场所仍为启用状态。
4. 仍失败时记录场所名称和错误提示交管理员排查，不要重复创建同名场所。

## 轮换链接

发现二维码链接泄露或需要作废旧码时，可以轮换令牌。轮换后旧二维码立即失效，需要重新下载和张贴。

云端单窗口切换时，现场会按批次打印并替换新二维码。全部场所切换完成后，旧二维码返回“二维码已更换”（HTTP 410），新二维码进入云端登记页。发现扫码失败、重复提交或登记状态长时间未更新时，应保留错误提示并联系管理员，不要重复创建场所或重复提交登记。

## 登记信息

公开登记页面的姓名、身份证号码、手机号、地址和照片均为必填项。浏览器会先提示明显的格式错误，云端接收服务还会校验身份证号码的出生日期和校验码以及手机号号段；校验失败的内容不会进入云端队列。姓名和地址只会去除首尾空白、合并连续空白，不会自动改写真实内容。

具备权限的人员可以按当前筛选查看或导出场所登记信息。登记记录中的“查看照片”会通过受保护接口读取照片，照片过期或被清理后会显示不可用。导出只用于规定业务，不得向无关人员转发。

## 饮酒报备码

管理员在“饮酒报备码”页签手动创建全所唯一二维码。只有云端同步状态确认后才能查看和下载二维码。扫码页面每次打开都会先展示六项规定，阅读倒计时结束后才能继续；规定关闭后不再显示重复查看入口。报备人和责任领导均须先填写双方姓名，再在手机或电脑的横屏签名区完成手写签名，签名区会显示对应姓名水印，备注说明可选。姓名、单位职务、饮酒时间、地点、事由、邀约人、出行方式和责任领导姓名均为必填项。

饮酒报备长期保存在滨湖平台本地业务库，可按饮酒时间和关键词查询；饮酒时间和服务器收到时间均按系统设置中的时区显示，详情中可以查看双签并按单条记录导出 A4 PDF。报备记录不要求照片，也不会写入场所登记表。点击“刷新”会主动拉取云端队列，并分别提示已入库、被校验拒绝、稍后重试或不确定状态；“当前没有可处理的云端登记”只表示本次没有可租约的记录，不代表历史记录已删除。二维码停用、轮换和导出操作需要相应的 `venue.manage`、`venue.view` 或 `venue.export` 权限。
