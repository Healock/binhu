# 用户、权限与系统管理

## 用户管理

超级管理员可以创建账号、关联人员、调整显示姓名和权限组。账号与人员资料是两层关系：人员记录描述真实岗位和社区，账号决定登录与权限。已关联账号的人员不要随意删除或重复创建。

## 权限组

权限组决定用户能看到哪些菜单、访问哪些接口以及数据范围。修改权限时：

1. 明确岗位需要完成的业务。
2. 只授予必要权限。
3. 同时检查查看、编辑、管理和数据范围。
4. 使用测试账号验证菜单隐藏和后端拒绝都有效。

仅隐藏菜单不等于权限控制，后端必须继续鉴权。

## 公告

具备公告管理权限的人员可以发布重要通知。公告正文应简洁，不包含身份证号、手机号、密码、令牌或业务原始数据。

## 系统设置

系统设置包括维护模式、系统时间、统计岗位和其他平台级配置。启用维护模式前要填写明确说明和时间，维护结束后确认普通账号已经恢复访问。

居住证平台首次登记识别的完整账号按社区保存在“社区管理”中。系统设置可多选后台只读查询范围，并维护接口地址、统一密码和查询间隔。列表只允许选择已启用且已配置账号的社区；页面会明确提示缺少的项目。每条任务按所属社区使用对应账号和独立会话，未勾选社区不会改用其他社区账号代查。该功能只读取居住证平台资料，不执行登记、开户、写回或密码重置。

管理员和超级管理员可以进入“服务器 MAC”页面，修改服务器执行居住证只读查询时使用的 MAC。保存会清除旧登录会话，后续查询自动使用新地址重新登录。服务器 `23333` 端口继续兼容既有读取方式，但不接受匿名写入；所有修改都必须通过登录后的权限接口完成。服务器 MAC 与普通用户在离线模式中维护的本机 MAC 候选列表、当前地址和社区授权检测结果相互独立。

## 部门管理

“部门管理”维护行政编成和部门树。管理员可以建立单位级部门（例如社区警务队、片区、基础管控、管家码和综合指挥室），设置上级部门、关联片区和启停状态；社区级部门仍由社区管理维护并自动关联对应社区。部门树使用真实部门 ID 和递归上溯，不按 `department_type` 判断功能归属。

部门归属和权限组是两件事：部门归属表示人员属于哪一层行政编成，权限组表示账号可以执行哪些功能以及能看到哪些数据。平台后续的模块归属使用部门树，但不会替代原有权限组和数据范围检查。

平台同时保留两种“所属”口径：行政编成由 `_departments` 和人员部门关系维护，例如“社区警务队 → 中片 → 冬梅”；业务管辖由片区、社区和小区资料维护，用于统计、社区民警和网格范围。两者不能互相代替。片区的名称、负责人和社区归属仍以 `_areas`、`_area_leader_links`、`_communities.area_id` 为业务管辖权威；部门管理中的片区部门只通过 `area_id` 引用该记录，不复制片区负责人或社区清单。

有成员或下级部门的部门不能直接删除或停用。页面会显示成员和下级数量，并说明先调整人员归属、移动下级部门后再重试。暂时没有确定归属的人员可以保持未分配部门；历史“内勤”部门不再用于新人员归属，已有记录须按维护窗口中的内勤取消迁移处理。

### 内勤取消维护

历史“内勤”部门的人员归位不是启动时自动完成的。维护人员必须先备份
`PlatformData`，再通过独立脚本按 `measure → migrate --apply → verify` 执行：

```text
python -m migrations.internal_department_retirement measure
python -m migrations.internal_department_retirement migrate --apply --run-id <运行编号> --backup-manifest <备份清单> --expect-internal-members <人数> --confirm-remove-internal
python -m migrations.internal_department_retirement verify
```

脚本只处理人员部门关系和空的历史 `internal` 部门。目标部门不存在、人员归属不明确、发现共享部门或下级引用时会整批停止；“暂不指定部门”的人员会清空部门而不会被放入新的替代部门。真实维护必须保留备份清单、命令输出和连续重启后的归属核验。

## 编辑帮助文档

超级管理员进入“帮助”，打开任意文档后点击“编辑 Markdown”：

1. 修改标题、摘要和 Markdown 正文。
2. 在预览页检查标题、列表、表格、链接和代码块。
3. 保存后立即对所有用户生效。
4. 如果要放弃线上修改，可恢复为随版本发布的内置文档。

编辑采用版本校验。其他管理员先保存后，旧页面会提示冲突，不会覆盖新内容。审计只记录文档、版本和字符数量，不记录正文。
