# 通用流程引擎（B1）

## 本阶段范围

B1 提供后端流程定义、发布版本、发起实例、处理任务、退回重提和超时推进接口。表单渲染器、流程配置页面和待办列表属于后续阶段；当前管理员通过 JSON 定义顺序节点。旧工单接口不用于新流程，饮酒报备也没有专用实现。

## 流程定义

节点保存在 `process_versions.nodes_json` 数组中，数组顺序就是执行顺序，不配置 `edges`。每个节点声明稳定的 `node_key`、显示名称、处理人类型及参数、`multi_mode`、空候选策略和超时设置。B1 仅支持 `multi_mode: single`；并行、会签和 `condition` 分支字段暂不执行。

处理人类型包括指定成员、发起人自选、表单联系人字段、直属主管、部门主管、岗位和发起人本人。解析器返回候选人员 ID 快照，不代替审批人作决定。当前部门表没有负责人列，因此部门主管候选由节点 JSON 显式配置 `assignee_params.user_ids`，或按部门配置 `assignee_params.user_ids_by_department`；不从岗位名称猜测负责人。创建实例时必须指定已发布的 `process_version_id`；后续发布新版本不会改变在途实例。

## 超时与升级

T1 到期时，在同一任务上增加同部门、同岗位的在岗人员，排除原主处理人；原处理人仍可处理。T1 没有额外候选时继续等待 T2。T2 根据独立的岗位顺序配置尝试向上一岗位扩展，范围仍限定在同一部门。岗位顺序为空、到顶或没有可用人员时，任务和实例进入管理员挂起状态，并向管理员发送通知。一次升级只修改原任务的候选人快照和阶段，不创建升级副本。

## 退回与重提

退回不更换实例编号，原任务保留为退回记录。发起人重提时创建新任务，阶段从零开始并重新计时；直属主管等处理人会依据新表单重新解析。每次提交和重提都在流程事件中保存完整表单快照，便于还原提交时的内容。连续退回达到三次后，实例转入管理员挂起处理。

## 附件与数据边界

新流程附件记录保存在 `process_attachments`，不复用旧工单附件表。普通事件记录只存本流程必要的动作和快照；业务端仍需按授权控制详情读取。B1 数据表通过 `domain_schema.py` 在 WorkflowData 初始化，不使用裸 SQL 迁移脚本。

当前没有流程管理或待办前端。真实 MySQL 建表、事务行为和目标环境运行尚需在部署前验证；本地自动化测试不代表生产验收。
