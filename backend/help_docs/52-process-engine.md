# 通用流程引擎（B2）

## 配置流程

在“系统设置 → 流程配置”中先建立表单定义，再建立流程定义并绑定表单。表单支持单行文本、多行文本、数字、日期、日期时间、下拉单选、人员选择器、附件照片、静态提示块和分组；字段使用稳定 `key`，可配置必填、最大长度、枚举选项和附件数量上限。附件照片控件当前仅展示不可提交提示，实际上传接口接入后再开放选择，因此附件字段暂不能配置为必填；发布校验会拒绝这类配置，运行时提示块也不注册表单校验项，不会阻止提交。流程节点使用列表编辑，可上下移动；每个节点固定配置 `node_key`、`name`、`assignee_type`、`assignee_params`、`multi_mode`、`empty_policy`、`timeout_hours`。保存草稿不会影响在途实例，发布后版本冻结，新的实例才使用新版本。

停用只影响新实例，历史实例仍可查看和处理。发布时后端会校验字段类型、必填限制、枚举值、附件上限以及处理人参数；前端提示不能替代后端校验。

## 待办与管理员放行

“工单中心”按任务上的 `assignees` 快照显示当前账号的待办；“我发起的”按发起人显示实例。详情包含节点进度、当前处理人、超时阶段和事件流。只有当前任务 `assignees` 中的账号能同意、驳回或退回修改；管理员默认只读普通任务。

岗位顺序为空、升级到顶或连续退回三次时，实例进入 `admin_hold`。管理员在详情的“管理员挂起”区域选择新的处理人并继续，或强制终止；两种操作都会写入 `process_events`，并产生管理员通知。超时提醒、升级通知和挂起通知均使用平台现有通知设施。

## 本阶段范围

B2 在 B1 后端内核上提供流程配置、表单控件渲染、待办列表和实例详情；旧工单接口不用于新流程，饮酒报备也没有专用实现。

## 流程定义

节点保存在 `process_versions.nodes_json` 数组中，数组顺序就是执行顺序，不配置 `edges`。每个节点声明稳定的 `node_key`、显示名称、处理人类型及参数、`multi_mode`、空候选策略和超时设置。本阶段仅支持 `multi_mode: single`；并行、会签和 `condition` 分支字段暂不执行。

处理人类型包括指定成员、发起人自选、表单联系人字段、直属主管、部门主管、岗位和发起人本人。解析器返回候选人员 ID 快照，不代替审批人作决定。当前部门表没有负责人列，因此部门主管候选由节点 JSON 显式配置 `assignee_params.user_ids`，或按部门配置 `assignee_params.user_ids_by_department`；不从岗位名称猜测负责人。创建实例时必须指定已发布的 `process_version_id`；后续发布新版本不会改变在途实例。

流程可以通过通用脚本从 JSON 幂等加载到 WorkflowData：

```bash
python -m tools.load_process_definition --file process_definitions/drinking_report.json --created-by <管理员账号 ID>
```

加载器只处理通用的表单、版本和有序节点数据；同一份 JSON 重复执行不会创建重复版本。饮酒报备定义位于 `backend/process_definitions/drinking_report.json`，不在引擎或前端写业务专用分支。

## 超时与升级

T1 到期时，在同一任务上增加同部门、同岗位的在岗人员，排除原主处理人；原处理人仍可处理。T1 没有额外候选时继续等待 T2。T2 根据独立的岗位顺序配置尝试向上一岗位扩展，范围仍限定在同一部门。岗位顺序配置保存在平台域 `PlatformData._system_config` 的 `process_position_order` 项中，数组按岗位从高到低排列，例如 `["所长","组长","组员"]`；执行器通过域路由使用当前工作流请求的游标读取。配置缺失或为空数组表示不升级并将任务挂起，同时通知管理员。到顶或没有可用人员时也进入管理员挂起状态。一次升级只修改原任务的候选人快照和阶段，不创建升级副本。`node_type=start` 是通用的自动通过发起节点，通常作为流程数组第一项；它不会生成待办，直接进入下一节点。

## 退回与重提

退回不更换实例编号，原任务保留为退回记录。发起人重提时创建新任务，阶段从零开始并重新计时；直属主管等处理人会依据新表单重新解析。每次提交和重提都在流程事件中保存完整表单快照，便于还原提交时的内容。连续退回达到三次后，实例转入管理员挂起处理。

## 附件与数据边界

新流程附件记录保存在 `process_attachments`，不复用旧工单附件表。普通事件记录只存本流程必要的动作和快照；业务端仍需按授权控制详情读取。流程数据表通过 `domain_schema.py` 在 WorkflowData 初始化，不使用裸 SQL 迁移脚本。

## 饮酒报备（PC）

饮酒报备是一个数据定义的直线流程：`发起 → 直属领导审批`。表单包含姓名、单位职务、饮酒时间和地点、事由、出行方式、家属电话、参加信息、风险询问、备注、直属领导人员选择器和六条禁令静态提示。直属领导字段使用现有“表单联系人字段”处理人类型；表单默认值由组织规则带出，发起人可以修改，提交时随表单快照固化账号 ID。当前只验收电脑端，手机端不属于本阶段范围。

真实 MySQL 建表、事务行为和完整生命周期仍需在 CI 隔离三库和部署前验收；本地自动化测试不代表生产验收。
