# 滨湖场所码云端接收服务

该目录是部署到独立云服务器的公网接收服务。它只保存场所公开名称、令牌摘要、加密登记正文和加密照片，不连接滨湖平台数据库。真实服务器地址仅通过部署环境变量和私密运维记录提供。

生产部署必须通过 `deploy/venue-cloud/` 中的固定脚本完成。私钥、HMAC 密钥、数据库密码和证书不得写入仓库；服务只监听 `127.0.0.1:48727`，公网访问统一经过 Nginx。

公开登记由三个浏览器请求组成：`/venue/{token}` 页面、`/api/public/venues/{token}` 元数据和 `/api/public/submissions` multipart 提交。部署 Nginx location 对这三个精确范围覆盖继承的主机 Lua WAF，避免共享场所出口 IP 在读页面阶段被临时封锁；例外不能扩展到其他路由或全局关闭 WAF。Receiver 仍负责页面/令牌校验、图片内容、幂等和应用层限流，Nginx 仍限制请求体为 6 MB；公开路径只使用不含请求正文的脱敏访问日志。其他公共表单和内部接口继续使用既有 WAF 保护。

开发检查：

```text
python -m pytest cloud/venue-receiver/tests
```

生产所需密钥文件：

- 滨湖登记接收 RSA 公钥：`<key_id>.pem`；
- 滨湖请求签名 Ed25519 公钥；
- 云端响应签名 Ed25519 私钥；
- Nginx mTLS 客户端证书签发 CA。

正文与照片采用每条提交独立的 AES-256-GCM 数据密钥，数据密钥由 RSA-OAEP-SHA256 封装。云端没有对应私钥，无法独立解密登记内容。

Receiver 固定使用单个 Uvicorn 进程。新提交会唤醒本进程内的长轮询请求；进程重启、通知丢失或以后改成多实例时，`wait` 接口在超时前后重新查询 MySQL，因此数据库队列仍是最终依据，不依赖内存通知保证交付。
