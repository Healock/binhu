# Staging 白名单副本准备器

本模块提供 `control measure/export`，用于在生产服务器受保护边界内生成
独立编号的脱敏材料；`apply_control measure/create/import` 可向独立候选八库导入。
尚未提供应用切换；报告中的
`ready_for_application_switch=false` 必须保留，不能把导出成功当作 Staging 验收。

```sh
python -m deploy.environments.staging_data.control measure
python -m deploy.environments.staging_data.control export
```

入口固定检查生产 backend 的项目、服务、环境、运行状态以及内存和磁盘余量，
在其独立 Python 进程内使用只读一致性事务；主应用进程、生产配置和数据不变。
生产密码仅由容器内已有设置交给数据库驱动，不进入命令参数、材料或日志。
原始业务字段只在内存中处理，不生成原始数据库 dump；数据库异常不回显参数。
服务器证据根目录固定为 `/srv/deploy-backups/environment-triad/staging-snapshots`。
每次使用新编号、0700 目录和0600文件；失败记录、代码哈希和容器基线独立保留。

当前白名单覆盖社区/片区、人员/部门关系、独立假账号标识、小区、房屋、
房屋小区关系、七类当前任务、本地来源、当前任务关联的研判流程和登记关系。
任务与本地业务表的 ID/业务键集合必须一致，外部来源和悬空引用直接拒绝。
账号密码、会话、权限组、照片、附件、外部配置以及未知字段不导出。
同一快照中的主键重新分配，核查员假名与人员管理保持一致；账号初始不可用，
实际密码初始化属于后续 Staging 导入步骤，不能从生产账号推导。

地址映射按社区隔离，住房类型只保留已审核枚举，其他自由正文替换。
版本号保留原值；旧哈希是否与当前来源一致的语义保持，不能洗掉版本冲突。
嵌套 JSON（包括 JSON 字符串和转义 Unicode）同样扫描敏感字符串叶子。
这是一道选定源值的精确扫描，结合封闭输出格式使用，不是任意 PII 检测器。
虚构证件号码采用无真实行政区含义的测试前缀，不保证通过外部行政区校验。

已支持历史动作摘要、任务人工地址确认和候选库 Staging 专属登记 HMAC 重建。
应用切换前仍须完成候选库真实导入、完整目标验证、投影重建及切换/回退验收。
报告显式列出未通过门槛。
旧 `staging_snapshot.py` 的简化 JSONL 工具不能替代本模块的关系和敏感值验收。

地址类型采用当前业务接口的封闭枚举：`community`、`apartment`、
`construction_dormitory`、`other`。未知值仍拒绝；不能通过允许任意字符串解决导出失败。

## 失败诊断与业务类别

房屋、组织、任务转换和最终扫描使用相同的扫描入口。失败报告只接受已审核的
逻辑表名、字段名和数量，不接受任意 ASCII 字符串或原始业务值作为诊断标签。
来源和业务表不一致时，额外统计 active/archived 本地来源登记、归档业务键和
重复业务键数量；归档中存在同一个业务键不等于当前任务已归档，不能据此排除。

核查结果采用当前 `TASK_WORKFLOWS` 的封闭选项，住房类型采用现有封闭分类。
同一个词出现在原始备注中，不会使经过枚举复核的结果选项变成备注正文。
这类同值情况在 `categorical_value_overlaps` 单列统计；敏感正文命中仍阻止导出。
结果字段的识别仅适用于对应业务表，或 parser_type 与完整字段合同均匹配的
来源 JSON。其他字段、任意嵌套 JSON 和未知结果继续拒绝或执行严格精确扫描。

2026-09-11 标准只读预检确认模型三业务表 261 条、当前来源 0 条，261 条均有
active 本地登记。用户已批准仅在 Staging 副本中恢复这些来源；生产不变。
`--recover-model-three-sources` 显式启用恢复，默认关闭。只恢复模型三，最多
261 条；逐条核对唯一 active `_local_source_records` 的业务 ID、业务键、完整
字段、内容哈希、非空来源标识及有效 revision。非 active、重复、缺失、内容冲突、
存在非本地当前来源或超出数量范围均拒绝。房屋登记关系不能代替本地来源台账。
恢复前的实际来源数量和恢复数量分别记录；revision 沿用台账，不能编造为 1。
所有恢复只在一致性只读事务的内存材料中进行，再经过原有脱敏和关系门禁，
不向生产补写投影，不把旧归档记录当作当前任务已经归档的依据。

服务器执行时必须从确定提交整体打包该模块及其依赖到新的私密证据目录，
核对归档和逐文件哈希。不能只覆盖服务器的两个 Python 文件并复用旧模块。
工具加载阶段失败也写入独立固定原因码材料；原始异常路径和参数不回显。
