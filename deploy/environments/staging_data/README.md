# Staging 白名单副本准备器

本模块目前提供 `measure` 与 `export`，用于在生产服务器受保护边界内生成
独立编号的脱敏材料。尚未提供数据库导入或应用切换；报告中的
`ready_for_application_switch=false` 必须保留，不能把导出成功当作 Staging 验收。

```sh
python -m deploy.environments.staging_data.control measure
python -m deploy.environments.staging_data.control export
```

入口固定检查生产 backend 的项目、服务、环境、运行状态以及内存和磁盘余量，
在其独立 Python 进程内使用只读一致性事务；主应用进程、生产配置和数据不变。
生产密码仅由容器内已有设置交给数据库驱动，不进入命令参数、材料或日志。
原始业务字段只在内存中处理，不生成原始数据库 dump；数据库异常不回显参数。
服务器证据根目录固定为 `/srv/deploy-backups/environment-triad/staging-snapshots`。
每次使用新编号、0700 目录和0600文件；失败记录、代码哈希和容器基线独立保留。

当前白名单覆盖社区/片区、人员/部门关系、独立假账号标识、小区、房屋、
房屋小区关系、七类当前任务、本地来源、当前任务关联的研判流程和登记关系。
任务与本地业务表的 ID/业务键集合必须一致，外部来源和悬空引用直接拒绝。
账号密码、会话、权限组、照片、附件、外部配置以及未知字段不导出。
同一快照中的主键重新分配，核查员假名与人员管理保持一致；账号初始不可用，
实际密码初始化属于后续 Staging 导入步骤，不能从生产账号推导。

地址映射按社区隔离，住房类型只保留已审核枚举，其他自由正文替换。
版本号保留原值；旧哈希是否与当前来源一致的语义保持，不能洗掉版本冲突。
嵌套 JSON（包括 JSON 字符串和转义 Unicode）同样扫描敏感字符串叶子。
这是一道选定源值的精确扫描，结合封闭输出格式使用，不是任意 PII 检测器。
虚构证件号码采用无真实行政区含义的测试前缀，不保证通过外部行政区校验。

后续导入前还须补齐历史动作摘要、任务人工地址确认、Staging 专属登记 HMAC、
候选八库重建/切换/回退和完整目标验证。报告显式列出未通过门槛。
旧 `staging_snapshot.py` 的简化 JSONL 工具不能替代本模块的关系和敏感值验收。
