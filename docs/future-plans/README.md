# Future plans 目录说明

`docs/future-plans/` 保存尚未完成的长期项目及相关执行台账。`docs/future-plans.md` 是唯一总目录；本目录中的文件负责记录单个项目的范围、约束、验收和后续状态。

## 维护规则

- 每个项目独立一个 Markdown 文件，文件名使用稳定英文 slug。
- 项目状态变化时先更新项目文件，再更新总目录。
- 计划文档不能替代代码、测试、部署或验收证据；描述已完成事项时必须链接对应提交、PR、测试或台账。
- 历史归档不回写。当前计划不得包含凭据、完整地址、身份证号、手机号或其他敏感业务正文。
- 新项目开始前重新核对 `AGENTS.md`、实际代码、环境身份、数据边界和当前 PR 状态。
- 当前环境统一称为生产环境、预发布环境和 Dev 环境；历史证据中的“影子环境”称呼保留。

## 拆分与恢复完整性

- 拆分前列出旧文档全部项目标题和子标题；段落位置与主题不一致时，按项目归属迁移，并保留日期、失败记录、停止条件及证据引用。
- 拆分后逐段核对旧正文都有落点，项目文件都在总目录登记；检查移动后的相对链接，不能只核对目录中有没有文件。
- 旧状态与新证据冲突时，在项目顶部记录核对日期和证据，历史台账不伪装成最新状态；附件中的历史操作授权不等于当前实施授权。
