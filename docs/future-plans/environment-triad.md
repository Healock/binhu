# 生产、预发布与 Dev 双环境建设

- 当前状态：实施中，尚未完成三环境上线验收
- 实施边界：生产继续承载真实业务；预发布使用脱敏副本；Dev 使用虚构数据

## 环境身份

| 环境 | 入口 | Cookie | 数据 |
| --- | --- | --- | --- |
| production | `/` | `binhu_session` | 真实业务 |
| staging | `/staging/` | `binhu_staging_session` | 生产脱敏副本 |
| development | `/dev/` | `binhu_dev_session` | 虚构或脱敏开发数据 |

入口路径、Bootstrap 身份、会话 Cookie、数据库和 Compose 项目必须一致。预发布账号使用
`observer@staging`，Dev 账号使用 `observer@dev`；账号不得跨环境登录。旧 `shadow` 只保留为历史证据，替代环境完成验收前不得清理。

## 数据与资源隔离

每套环境使用独立数据库、卷、网络、密钥、日志和资源上限。预发布和 Dev 禁止连接生产数据库、腾讯及其他生产外部写入服务；生产数据脱敏必须覆盖姓名、身份证号、手机号、地址正文、账号、来源正文和附件。

## 实施门禁

依次完成身份校验、资源检查、脱敏验证、账号跨环境拒绝、入口健康检查、预发布 75 人趋势复测后，才可停用 `observer@shadow` 和删除旧影子资源。清理前须将配置、容器/卷/网络清单、运行编号和压测结果保存到项目目录之外，并核对可读性、大小和 SHA-256。任何身份、隔离、资源或生产健康检查失败都应停止。

## 当前进度

代码已提供三种环境身份、环境专用会话 Cookie、固定 API 入口和前端路径隔离。Compose、脱敏导出、账号初始化、Nginx 路由、预发布压测及旧影子清理仍需在服务器上按门禁逐项完成，并分别记录验证证据。
