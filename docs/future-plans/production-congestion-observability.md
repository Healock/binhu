# 生产接口拥堵诊断与抗压治理

- 当前状态：已完成 2026-09-08 17:00–20:00（Asia/Shanghai）只读排查，整改未开始
- 文档类型：生产问题后续治理计划
- 实施边界：本文件不代表已经修改配置、代码、数据库或部署服务
- 关联时间窗口：2026-09-08 17:00:00–20:00:00（北京时间，结束时刻不含 20:00 之后请求）

## 已确认的只读证据

本次排查从生产 Nginx 访问日志、Nginx 错误日志、宿主机 journal、容器状态和 MySQL 只读状态指标取证。没有重启容器、修改配置、写数据库、清理日志或触碰压测资源。

目标窗口共记录 31,158 个 HTTP 请求，其中 30,746 个为 200；另有 65 个 503、51 个 500、61 个 422、145 个 401、17 个 499、10 个 409、12 个 404、7 个 403、2 个 400 和 42 个 304。单分钟局部峰值约 276 请求。

请求量主要由周期性和列表类接口构成：心跳 6,322 次、未读数 6,238 次、维护状态 5,024 次、全链条任务搜索 3,140 次、身份检查 2,236 次、事件流 1,543 次、编辑器读取 1,320 次、房屋搜索 813 次。该分布表明基础轮询和事件重连对总请求量有显著贡献。

503 主要落在全链条任务保存、领取和更新接口，也出现在少量场所码二维码接口。日志能确认服务端返回了 503，但不能仅凭访问日志区分 `task_save_timeout`、`task_save_busy`、`database_pool_busy`、维护暂停或其他业务错误码。

另有 51 个 500 全部集中在在线数据查询接口 `/api/query/全链条?source=online&page=1&page_size=200`，并呈近似固定周期重复，疑似存在失败后的客户端轮询或重试放大，具体调用方和后端异常仍需补证。

宿主机在该窗口没有查到 Docker/containerd 重启、内核 OOM 或磁盘错误；MySQL 容器也没有重启证据。当前只读 MySQL 指标显示连接未达到上限（`Max_used_connections=59`、`max_connections=151`），当前无行锁等待；累计行锁等待约 4,081 秒、最大单次约 50.9 秒，说明锁竞争是需要继续验证的风险方向，但不能据此认定为该时段唯一根因。当前累计 `Aborted_connects` 较高，也需要按时间和来源拆解。

## 尚未确认的假设

- 任务保存/领取 503 可能由行锁等待、死锁重试耗尽、连接池获取超时或应用忙保护触发。
- `/api/query/全链条` 的 500 可能由特定 SQL、投影数据或查询参数异常触发，客户端固定周期重试进一步放大压力。
- 事件流、心跳、未读数和维护状态轮询可能在多客户端同时在线时形成同步请求峰值。
- Nginx 曾出现 upstream reset/refused/prematurely closed 记录，但现有证据不足以将其精确归因到本次窗口。

## 后续治理计划

1. 为保存接口记录结构化安全指标：`operation_id`、脱敏任务定位、锁等待时间、连接池等待时间、重试次数和最终错误码；按 `task_save_timeout`、`task_save_busy`、`database_pool_busy`、`maintenance_paused`、409 冲突及业务 4xx 分开统计。
2. 复核保存事务的连接使用和锁顺序，确认持有 `online_data` 连接时不会从同一连接池嵌套获取第二条连接；统一来源、本地业务表、投影、任务图和汇总输入的锁顺序。
3. 修复 `/api/query` 的真实后端异常后，为查询、心跳、未读数、维护状态和事件流增加指数退避、随机抖动、失败熔断和合理缓存，避免固定周期重试风暴。
4. 建立按分钟的连接池、MySQL 锁等待、慢查询、503/500 错误分类、事件流重连和队列排空指标；保留 UTC 原始时间并按系统时区展示。
5. 在预发布环境执行 75 人、5 分钟突发复测，记录整体接口和地址匹配端到端 P50/P95/P99、错误率、连接池、锁等待、死锁、CPU、内存和队列排空时间，作为版本间趋势指标。
6. 只有在指标确认瓶颈后，才另立 PR 调整连接池、超时或后台任务并发；不得用单纯增大锁等待超时掩盖根因。

## 验收与停止条件

- 能按错误码解释每个 503/500，并关联到安全操作编号或请求类别；
- 查询失败不会无退避持续重试，事件流断线不会造成同步重连峰值；
- 保存失败保留草稿且不会产生并发重复事务；
- 75 人复测达到预先约定的成功率、P95/P99 和队列排空门槛；
- 真实 MySQL 验证、CI、部署和生产观察证据分别记录，不能以日志静态分析替代；
- 任一数据异常、锁等待来源不明、错误率未下降或容量指标未达标，停止上线并保留诊断证据。

## 明确不做

- 不在生产故障排查期间重启服务、清理日志、修改 Nginx、调整数据库参数或制造测试数据；
- 不把当前容器健康、累计 MySQL 指标或单次日志错误当作目标窗口的完整历史；
- 不恢复腾讯数据路径，不把本计划当作已完成修复、部署或容量承诺。
