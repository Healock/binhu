## 已解决事项的生产证据

## 仍需处理的事项

### R-005：OAuth 明文

数据库目前直接保存腾讯文档访问令牌。虽然应用已经配置独立加密密钥，但旧数据加密迁移
还没有实施，因此不能把这一项写成已解决。

迁移时要先备份，再实现新数据加密、旧数据兼容读取、分批迁移和回退验证。

### R-008：前端目录热更新

当前部署会在替换前端后重建后端容器，所以实际运行稳定。是否能只替换目录而不重启，
尚未单独验证，不应把猜测写成部署规则。

### R-009：异地备份

运维中心的每日备份与服务器故障可能同时丢失。重要数据还需要复制到另一台受控设备或
对象存储，并增加加密、保留时间和恢复演练。

### R-010：SSH 密钥

当前已经使用新的高强度密码，但仍允许 root 密码登录。家里和单位电脑分别配置自己的
SSH 密钥并验证后，可以关闭密码登录，进一步降低暴力破解风险。

### R-011：走访身份证号明文

走访明细的“操作人账号”是网格员身份证号。第一阶段按项目管理人确认的方案明文保存到
`t_visit_details`，并在网格员资料为空时补入 `_grid_members`。这是为了后续稳定关联人员，
但数据库或备份一旦泄露，完整号码也会随之泄露。

只有超级管理员可以在人员管理接口和页面查看、修正完整号码；普通管理员即使拥有人员敏感资料
权限，也不能获得填写状态、遮盖号码或完整号码。导入问题、操作记录、CSV 和日志仍不得返回完整
号码。这只能减少日常使用中的暴露，不能代替数据库加密。后续迁移需要先备份，再实现新数据
加密、旧数据兼容读取、分批迁移和回退验证。

### R-012：React Router 版本

2026-07-29 运行生产依赖审计时，当前 `react-router-dom` 和 `react-router` 6.30.4 报告两条
中等安全公告。平台当前没有使用 React Router 的服务端渲染，代码中的跳转地址也都是固定的
内部路径，因此已知受影响入口较少，但不能把它写成已经解决。

已修复版本需要升级到 React Router 7.x，属于主要依赖升级。应在独立分支中完成登录保护、
左侧栏、手机 Dock、设置页和未知地址跳转的完整回归，不在 `0.4.0` 的手机体验改造中顺带升级。

### R-013：旧出勤历史不完整

平台从 0.6.0 开始保存多条请假历史和每周双休日备勤。上线以前只保留人员当前或最近一次
请假，已经被覆盖的更早记录无法从数据库自动恢复。管理员可以按纸面或原系统记录补录过去
请假和历史周末排班；补录以前，页面会提示这段历史的人均日指标只能作为参考。

### R-014：统一初始密码公开

`0.9.0` 名单导入按项目管理人确认的方式，为新账号使用同一个初始密码，并通过全员公告公开。
这便于开发阶段集中开通账号，但任何看到公告的人都可能在账号本人第一次登录前尝试其他用户名。
唯一登录只能顶掉旧会话，不能阻止第一次抢先登录。

当前缓解办法是把新账号标记为临时密码并持续提醒本人尽快修改，名单、密码和导入过程不进入
Git、共享文档、日志或操作记录。更安全的正式方案是为每个人生成不同的一次性密码，或通过
私下渠道分别发放；届时再移除公开密码公告。

### R-015：人员管理入口可以创建账号

为了保持“一名业务人员对应一个账号”，拥有人员管理权限的管理员可以在新增人员时关联尚未使用的
普通账号，或同时创建新账号。这项能力不会开放用户管理、权限组选择或超级管理员创建：新账号只
能继承人员岗位的默认权限，用户名必须唯一，初始密码至少 8 位，人员和账号在同一事务中写入，
失败时整体回滚。请求正文、密码和完整用户名不进入操作记录。自定义权限仍只能由超级管理员在
用户管理中单独设置。

`0.9.4` 允许在人员管理中改绑账号。目标为空闲账号时释放旧账号；目标已关联另一名人员时交换
双方账号。两种情况都会清除受影响账号的有效会话，并按新人员岗位重新继承权限，避免登录中的
身份与数据库关联不一致。账号 ID 和是否互换可以进入审计，用户名和身份证号不能进入审计。

### R-016：超级管理员可读取完整身份证号

人员资料中的身份证号属于高敏感数据。`0.9.4` 为满足资料修正需求，只允许超级管理员从人员接口
读取和修改完整号码；普通管理员即使拥有人员敏感资料权限，也不会收到是否已填写、遮盖号码或
完整号码。接口请求、操作记录和日志不得记录完整号码。超级管理员账号被盗仍可能导致号码泄露，
因此应继续使用独立强密码、唯一登录和空闲退出，并定期检查账号与操作记录。
