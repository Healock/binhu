# 组长分配核查人性能专项

## PR 摘要

本 PR 优化流口任务分配工作台的查询、候选渲染和分配分块，减少列表读取完整 JSON、逐行地址排序和完成后的重复刷新。新增投影字段、复合索引和可恢复启动回填；前端使用虚拟化行并将分配分块调整为 100 条。Redis 事件订阅、候选缓存和实时失效不在本 PR 内。

### 解决了哪些问题

- 工作台查询过去需要读取完整 `values_json`，并在 SQL 中执行来源判断和地址表达式排序。
- 分配前端按 20 条分块，候选较多时渲染全部卡片并在完成/异常时重复加载工作台。
- 历史投影没有结构化的来源、地址和待分配字段，无法稳定使用索引。

### 使用了什么方式

- 代码/接口改动：工作台直接读取投影字段；接口新增 `duration_ms` 和 `query_mode=indexed_projection`；批量分配上限与前端分块调整为 100 条。
- 数据库或数据迁移：`_online_source_projection` 增加来源显示、地址显示、地址排序键和 `assignment_queue_ready`，增加全局/社区复合索引；启动时以 500 条一批执行命名锁保护、可断点续跑的历史回填。
- 前端交互或样式：候选按响应式完整行虚拟化，桌面端保留多列布局；每批成功任务从本地候选集合移除，完成后只触发一次外层刷新。
- 外部平台/腾讯接口：不访问、不写入任何外部平台；本 PR 继续使用本地任务来源和现有本地事务语义。
- 权限与数据范围：沿用现有任务管理权限、社区范围、来源版本和地址匹配校验，没有扩大权限。

### 数据与安全边界

- 是否修改数据库结构：是，新增投影字段、索引和 `_assignment_projection_backfill` 状态表。
- 是否修改生产数据：否；启动回填只补齐投影缓存字段，不修改原始业务任务。
- 是否向腾讯或其他外部平台写入：否。
- 是否新增权限或扩大数据范围：否。
- 日志/审计是否可能包含姓名、身份证号、手机号、地址、照片或来源正文：否；新增耗时日志和审计沿用现有安全摘要。
- 是否需要备份：`all`；涉及 `OnlineData` 投影结构与启动回填，建议 `backup_scope=all / release_scope=auto`。

### 建议怎么验收

1. 前置条件：从最新 `main` 部署到测试环境，准备虚构任务和已有地址匹配投影；确认 #479、#480 的合并顺序后再合并本 PR。
2. 操作步骤：
   1. 启动服务，观察回填状态可创建、运行、断点续跑并在完成后跳过。
   2. 以组长或有任务管理权限账号打开分配工作台，检查候选按地址排序、桌面多列/手机单列显示和接口耗时字段。
   3. 选择同一社区的任务，分别执行单人分配和平均分配，观察每 100 条一批的进度和局部移除。
   4. 使用虚构版本冲突、来源重复、地址不可靠和已完成任务，确认逐条跳过且不影响其他任务。
3. 预期结果：工作台不读取完整 `values_json` 做排序，候选最多返回 2000 条，分配每批最多 100 条，成功任务不重复出现，页面只触发一次外层刷新。
4. 失败或边界场景：回填失败应阻止服务就绪；SQL/连接异常应回滚当前事务批次；权限、社区范围和乐观锁校验保持原有拒绝行为。

### 风险、回滚与监控

- 主要风险：首次启动会执行历史投影回填，数据库规模较大时启动时间增加；新增索引会增加投影写入成本。
- 失败时会不会覆盖缓存、快照、业务表、归档或外部数据：不会覆盖原始业务字段；回填按批次事务更新投影，失败会记录状态并阻止启动就绪。
- 回滚方式：停止新版本，恢复上一版本代码；数据库字段和索引可保留，不影响旧查询路径。必要时按备份恢复 `OnlineData`。
- 上线后需要检查的接口、容器、日志或任务：检查启动回填状态、`assignment-workbench` 的 `duration_ms/query_mode`、批量分配阶段耗时及投影索引使用情况。
- 是否需要暂停自动同步或等待后台任务结束：否；当前生产本地数据源不依赖腾讯同步。
