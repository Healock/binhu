# 辖区资产：自购自住人员资料

## 数据类别

“自购自住明细”不是新的流口业务表，也不只是为了补齐模型三结果而维护的临时名单。它属于**辖区资产资料**，记录辖区内自购自住房屋的居住人员，后续可以作为房屋档案、人员档案和相关核查工作的基础资料。

当前首版先在数据上传中心导入，并将资料与模型三任务进行安全匹配。匹配更新是资产资料进入平台后的一个应用场景，不改变这类资料的业务归属。

## 处理规则

- 管理员在数据上传中心导入 ZIP；ZIP 内可包含多个 XLSX。
- XLSX 必须包含“居民证号”（兼容“身份证号/身份证号码”）列。
- 身份证先做格式校验，再按 HMAC 去重；原始 ZIP、工作簿行、房屋地址和房主资料不落库。
- 姓名、居民证号和“个人联系电话”按现有辖区档案敏感字段权限写入人员档案；导入审计和批次摘要只记录数量，不记录人员正文。
- 导入人员会按身份证 HMAC 复用或创建辖区人员档案，并直接在人员档案中显示“自购自住”标签；底层兼容标签记录通过 `registry_person_id` 关联人员档案，避免形成两套无法追溯的人员主记录。
- 当前首版只把资料匹配到 `疑似未注销模型三` 任务；模型三结果更新是资产资料进入平台后的一个应用场景，不改变资产资料的业务归属。
- 当前来源唯一、无冲突且“核查结果”为空或为“无法核实”时，平台填入“近期返吴”；后续全民防只读同步获得的新模型三任务也会再次按已导入名册匹配。来源重复或冲突的任务继续保留在来源异常中，不能用名单结果掩盖异常。
- 已有其他核查结果，或存在待处理的平台本地编辑时，保留原结果并计入“保留原结果”。
- 该功能只修改滨湖平台，不调用全民防登记或其他外部写入接口。

## 批次与安全边界

每次导入保存文件哈希、规则版本、数量摘要、导入人和时间；最近批次接口只返回安全摘要，不返回内部账号 ID 或原始名单内容。相同文件哈希不会重复导入。

数据库表名 `_qmf_self_owned_*` 和接口路径 `/api/qmf-source/self-owned/*` 是首版兼容命名，不代表这类资料属于全民防或模型三来源。

当前规则版本为 `self-owned-v2`。V2 将居民姓名、居民证号和个人联系电话完整写入受权限保护的人员档案，并将大名单写入改为分块处理。后续若小区或其他辅助信息加入匹配，应继续升级规则版本并补充脱敏 fixture，不能直接改变历史批次含义。

同一文件如果已经按 V1 导入，可以重新上传一次完成 V2 人员字段补齐；已经按 V2 导入的文件仍会被幂等拦截，避免重复创建档案、电话或标签。
