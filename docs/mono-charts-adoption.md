# Mono Charts 在滨湖智慧平台中的使用建议

## 已接入

### 社区在线核查完成情况

- 来源：Amicro `MonoRoundedStackedBarChart`。
- 平台改造：从演示用的竖向季度柱改成横向社区堆积条，继续展示已完成、无法核实和其他待完成。
- 原因：12 个中文社区需要完整显示名称，横向布局比直接照搬四列演示图更易读。
- 依赖：只引入底层 `recharts`，组件源码保留在平台仓库中，并使用平台自己的主题变量、响应式规则和无障碍摘要。

## 推荐后续采用

| 优先级 | Mono 组件 | 平台候选位置 | 适用理由 |
| --- | --- | --- | --- |
| 高 | Rounded KPI Card / Sparkline | 岗位仪表盘、运维中心 | 适合“当前值 + 短期趋势”，能替代只有孤立数字的卡片。前提是接口已有连续时间序列。 |
| 高 | Rounded Bullet Chart | 走访目标、在线核查目标 | 同时表达目标、已完成和差额，比仪表盘仪表盘式圆环更紧凑。 |
| 中 | Rounded Line / Area Chart | 外部数据获取运行记录、同步成功率 | 适合展示耗时、成功量、失败量随时间的变化；没有历史序列时不应伪造。 |
| 中 | Rounded Donut / Radial Gauge | 工单或任务状态概览 | 只适合 3—5 个稳定分类，不用于社区等长列表。 |
| 中 | Rounded Heatmap | 工作贡献日历 | 当前已有成熟热力图，只有在视觉统一收益明确时再替换，避免重复依赖和回归风险。 |
| 低 | Rounded Waterfall | 批次导入差异解释 | 仅在需要表达“原始量 → 跳过 → 冲突 → 成功”的增减关系时使用。 |

## 暂不建议采用

- 雷达图：不同指标量纲难以统一，容易制造看似直观但不可比较的面积。
- 漏斗图：平台多数任务并非严格单向转化流程，使用漏斗会误导。
- 桑基图：只有形成稳定的跨状态流转统计后才有意义，当前不应根据页面状态临时拼接。
- 气泡图、极坐标图、蜡烛图、金字塔图：与现有业务问题没有直接对应关系。
- 大量微交互动效：任务处理以密度和稳定为先，动画只用于状态变化和图表首次呈现，并尊重减少动态效果设置。

## 接入原则

1. 先确认图表回答的业务问题，再选组件，不能为了好看反推指标。
2. 组件源码进入平台仓库，颜色、间距、深浅色和移动端规则统一使用平台变量。
3. 图表必须保留文本摘要、悬浮提示和可追溯的明细入口。
4. 不一次性引入整个 Amicro 运行时；按需采用底层依赖和单个组件，控制主资源体积。
5. 第三方源码必须保留许可和来源说明。

## 本轮（0.25.11）已接入

- 个人仪表盘：近 7 日实际工作量 Sparkline。
- 在线核查与走访：以现有真实计数计算的完成目标 Bullet Chart；目标语义是“当前范围全部数据”，不使用臆造的每日指标。
- 下发任务：待审核、待发布、已发布三类状态 Donut；异常状态仍保留在原有数字卡片中，避免把可能重叠的状态误算成互斥总和。
- 运维中心：腾讯请求额度和同步任务的真实 14 日趋势图，原始表格继续保留。
- 数据上传中心：照片批次结果构成图，直接展示可匹配、未匹配、冲突、重复和失败的互斥统计。
- 贡献热力图：继续使用现有 `@uiw/react-heat-map`，只统一为更柔和的圆角单元格。

这些图表均按页面懒加载，保持首屏资源体积可控；所有图表同时保留文字摘要、Tooltip 和明细表格，验收不满意时可以按组件或页面单独撤回。
