# 流口任务本地优先写回说明

## 范围

首版覆盖流口指令核查的普通核查、研判和批量分配。平台保存立即生效，腾讯写回异步执行。Univer
原始表格编辑及原始行新增、删除暂不切换，继续使用现有同步写回。

## 合并规则

| 腾讯变化 | 平台待写回字段 | 处理结果 |
|---|---|---|
| 没有变化 | 任意授权字段 | 写回腾讯并回读确认 |
| 只变化其他字段 | 任意授权字段 | 吸收腾讯变化，继续写回平台字段 |
| 同一字段已等于平台值 | 同一字段 | 视为已同步，清除待写回 |
| 同一字段变为第三个值 | 同一字段 | 保留平台值并进入冲突，不自动覆盖 |
| 来源行移动 | 任意字段 | 按业务主键迁移物理行，保留来源 ID |
| 来源行删除或业务主键替换 | 任意字段 | 保留冲突投影，仅允许采用腾讯结果撤销平台值 |

## 运行状态

- `pending`：已经保存到平台，等待腾讯写回。
- `retry`：腾讯访问失败，五分钟后自动重试。
- `conflict`：腾讯同字段变化或来源行消失，需要人工选择。

服务重启会把遗留的 `processing` 恢复成 `retry`。后台调度每五秒扫描到期记录；立即写回任务失败也不会
回滚已经提交的平台值。

## 上线前确认

1. 使用受控测试行验证平台修改后腾讯回读一致。
2. 分别验证腾讯修改其他字段和同一字段。
3. 验证腾讯排序、插行和删除后的来源定位。
4. 验证服务重启后待写回记录继续重试。
5. 确认访问日志和普通管理审计只包含来源 ID 与字段名，不包含居民字段值。

尚未确认：生产腾讯表在大量排序后出现完全重复业务主键时，只能按最近物理位置稳定配对，无法证明
哪一条重复行是原行。此类任务仍应保持来源异常并由人工逐条核对。
