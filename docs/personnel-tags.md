# 人员标签

“人员标签”用于维护需要长期识别和筛选的特殊人员。目前平台预置四个核心分类：

- 通勤人员
- 五失人员
- 重点人员
- 精障人员

人员标签已整合到“辖区档案 → 人员档案”：人员列表直接显示当前有效标签并支持多标签筛选，人员详情保存有效标签和完整历史，具备维护权限的用户可以直接添加或解除标签。原独立“人员标签”导航已移除，旧 `/watch-people` 地址跳转到辖区档案。

内部数据库表、权限代码和接口路径仍保持原有兼容名称，旧数据通过 `registry_person_id` 关联人员档案；尚未建立显式关联的历史数据继续按身份证 HMAC 安全匹配。标签查看和维护权限没有扩大：只有 `registry.watch.view` 可查看和筛选，只有 `registry.watch.manage` 可添加或解除。同一人员按身份证号唯一归档；同一分类只保留一条当前有效标签，重复来源行作为来源记录保留，不重复创建人员或标签。

## 通勤人员名单导入

历史批量导入表、接口和批次数据继续保留，避免破坏已经形成的人员、标签与任务快照。预览只返回数量、分类和安全状态，不返回名单正文；确认前发现身份证为空、身份证格式或校验位异常、姓名冲突、手机号冲突、已有档案停用或姓名不一致时会阻断导入。

导入支持有表头名单和“姓名 + 身份证号”两列的无表头名单。身份证会清理首尾空格、全角空格、末位 `x/X` 和明确的 Excel `.0` 尾缀，并执行出生日期与校验位检查；不会猜测异常号码。来源手机号只会幂等补充到对应人员档案。

名单通常只到派出所级别，平台不会猜测社区归属。确认导入后，现有在线任务会在下一次正常同步时补齐人员标签快照；导入本身不会修改腾讯在线表或制造测试任务。

## 本地基准统计

用于本地验证的三份通勤名单合计 1,528 条来源行，按身份证去重后为 1,291 人；来源行重复不会重复建档。统计过程中未发现身份证、姓名或手机号冲突。正式生产导入仍必须由超级管理员在部署后的预览页面再次核对，并在确认前完成 `RegistryData` 备份。
