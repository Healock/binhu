## 部署、回滚与证据

1. 发布提交合并 main、CI 通过后，固定 Deploy production 网关按精确 SHA 执行 `backup_scope=all`、`release_scope=full`。
2. 备份全部业务数据库与旧程序，校验备份、部署身份、健康和版本；生产只读验收，不创建虚构业务记录。
3. 客户端自动发布可能先于部署触发；需要时暂停该次工作流，生产验收后从相同 SHA 重新执行。客户端工作流负责创建公开版本标签，不能提前创建同名标签导致发布失败。
4. 人工无匹配状态与历史为新增兼容结构。出现回滚需要时先停相关写入与 worker，备份并检查旧代码兼容性，禁止让不识别该状态的旧 worker 覆盖人工结论。程序回退不等于数据库回退。
5. 独立 MySQL 证据先复制至项目外 `/srv/binhu-release-evidence-r2810-20260908a`，核对清单和 SHA-256；保留原卷及失败证据，禁止全局清理。
