# 疑似未注销模型三来源接入

## 数据来源与筛选口径

平台从旧居住证系统的只读接口读取“疑似未注销模型三”待核查任务：

```text
GET /api/masses/queryYysList
judgeType=yys
hcjg=0
```

`hcjg=0` 表示未核查。请求由后端发起，浏览器不会接触旧平台账号、密码或令牌。接口只读，不调用旧平台的登记、写回或删除接口。服务端按配置的派出所编码和名称再次校验范围；范围不符的记录会计入问题统计而不会进入任务库。

分页采用每页 200 条，并有最大页数和最大记录数保护。网络错误以及 502/503/504 只做一次有限重试；重复分页、业务错误、认证失败和超出保护阈值直接使本次读取失败，避免循环读取或覆盖已有任务。

## 字段映射

旧平台字段在适配层转换为本平台模型三字段：

| 旧平台字段 | 平台字段 |
| --- | --- |
| `endTime` / `deadline` / `jzsj` | 截止时间 |
| `hcczr` / `inspector` / `checker` | 核查人 |
| `xm` / `name` | 姓名 |
| `sfzh` / `identity` | 身份证号 |
| `lxfs` / `phone` / `mobile` | 联系方式 |
| `dz` / `address` | 地址 |
| `jgmc` / `sqmc` / `community` | 下发社区 |
| `hcjgtext` 等结果字段 | 核查结果（新任务为空） |

适配层会在本轮处理期间保留内部来源引用：旧平台组织/下发编码 `xfsq`、来源行 ID 和来源更新时间。这些值只用于社区解析、幂等同步与问题统计，不写入用户可编辑业务字段。

## 社区与组织编码

旧平台 `xfsq` 是 12 位组织/下发编码；全民防正式社区代码是另一套 10 位编码，两个命名空间不能直接比较。社区管理中维护的“全民防组织编码”用于把旧平台任务映射到正式社区，一个组织编码只能绑定一个社区，但一个社区可以维护多个编码。

解析顺序如下：

1. 先按启用的组织编码精确匹配；
2. 编码对应多个社区时返回歧义，禁止猜测；
3. 没有组织编码配置时，使用旧平台社区名或社区别名匹配；
4. 芦荡等别名按照社区管理中的别名归入正式社区（例如芦荡归入长板）；
5. 编码和名称均无法匹配的数据进入未解析问题统计，不自动导入正式任务。

## 同步与失败处理

来源开关默认关闭：

```text
QMF_SOURCE_ACQUISITION_ENABLED=false
QMF_SOURCE_AUTO_SYNC=true
QMF_SOURCE_BASE_URL=（为空时复用 VISIT_SOURCE_BASE_URL）
```

生产环境应显式配置 `QMF_SOURCE_BASE_URL` 指向旧平台模型三 API 主机（例如
`http://10.91.0.15:9091`），不要把全民防登记专用的 `QMF_API_BASE_URL` 当作该来源地址。

开启后，模型三来源作为独立的同步阶段接入现有任务同步链路。空结果或读取异常不会删除上一次成功同步的本地任务；无法匹配社区的记录只进入问题统计。写入本地任务时使用身份证号和联系方式组成的稳定业务键，重复同步不会创建重复任务，并尽量保留本地已填写的核查人、核查结果和备注。

过渡期间，旧平台虚拟来源可能与原腾讯模型三来源同时存在。若两条来源的业务主键和标准化内容完全一致，投影、任务详情、批量分配和反馈扫描只把它们视为一个逻辑来源，并优先保留可写的腾讯来源；原始来源行仍保留用于追溯。若内容不同，则继续按多来源异常处理，禁止自动选择或覆盖。

本阶段只负责旧平台任务的只读获取和本地任务入库，尚未改变现有腾讯模型三来源的读取/写回逻辑，也不把旧平台记录伪装成腾讯来源行。真实核查结果的写回仍按原有来源和权限规则执行。

## 运维与安全边界

- 旧平台认证配置只放在服务端环境变量；不得写入 Git、前端包、普通日志或审计正文。
- 日志只记录阶段、统计数和安全错误码，不记录身份证号、姓名、电话、地址或响应正文。
- 生产启用前应先用只读预览核对来源总数、可匹配社区数、未解析数和重复数，再执行幂等回填。
- 生产环境没有独立测试库时，不使用真实任务做测试；自动化测试使用虚构数据和 HTTP MockTransport。
