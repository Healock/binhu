# 居住证平台多社区范围与账号隔离设计

## 背景与目标

系统当前的居住证平台配置只能保存一个“登录社区”，后台查询任务也因此使用单一社区账号。需要把它改为可多选的查询范围：用户勾选哪些社区，平台就只对这些社区执行居住证平台只读查询；每条任务必须使用其所属社区自己的账号和会话，不能用另一个社区账号代查。

本设计不恢复居住证平台真实登记、房屋开户、密码重置、写回或其他外部写接口。居住证平台在本项目中继续是外部只读来源。

## 配置与兼容性

新增系统配置键 `residence_login_community_ids`，值为规范化 JSON 正整数数组，例如 `[12,18]`。保存时去重并排序，拒绝非正整数、未知社区、停用社区和未配置居住证用户名的社区。启用居住证只读扫描时必须至少选择一个社区。

现有 `residence_login_community_id` 保留为过渡兼容字段。读取配置时优先使用数组；仅当数组不存在或为空时，才把旧单值转换为单元素数组。保存新格式后运行时不再依赖旧字段，必要的单数属性只作为兼容投影提供给尚未迁移的调用方。

配置读取接口返回选中的社区 ID、名称和安全的配置状态，不返回用户名、统一密码、session token 或个人业务资料。保存接口返回服务端规范化后的数组和社区名称，前端以该结果刷新状态。

离线模式的“刷新在线配置”同步接口、MAC、超时、启用状态和所选社区的 ID、名称及非敏感组织代码，不同步任何账号、统一密码或 session。离线端按所选社区建立独立的本机账号槽位，使用者逐社区填写完整账号；统一密码仍只保存在当前客户端。远端范围变化时仅保留仍在范围内的本机账号，不得用一个社区账号代替另一个社区查询。

## 前端交互

“登录社区”使用可搜索多选控件。只有启用且已配置居住证账号的社区可选择；停用或未配置账号的社区保留在选项中并显示不可选原因。已选社区按正常多选标签和折叠规则展示，窄屏不得撑破配置表单。

页面提交 `login_community_ids` 数组，不新增冗长的实现说明文案，也不显示社区用户名、密码或 token。旧接口只返回单社区字段时，前端使用兼容回退；数组字段存在时始终优先。

## 运行时路由与会话隔离

任务处理先根据任务正式社区解析出唯一的社区 ID，再验证该社区是否在当前选中范围内。范围内的任务使用该社区自己的居住证用户名、统一密码和 `community_<id>` 会话键。社区 A 的 session、组织代码和登录结果不得用于社区 B。

未选社区返回安全错误码 `community_out_of_scope`，不向居住证平台发起请求，也不回退到其他社区账号。社区账号缺失、组织身份不匹配或响应结构不符合合同同样直接失败。范围变化时清除受影响社区的缓存 session，避免旧账号继续复用；未变化社区的有效会话可以保留。

现有只读 client 的请求路径、认证失效处理、响应身份校验和日志脱敏继续有效。实现不得新增外部登记、开户、写回、删除或密码重置调用。

## 数据流

```text
配置页面多选社区
        -> 配置 API 校验并保存 ID 数组
        -> 只读扫描读取任务正式社区
        -> 匹配选中社区及其账号
        -> 读取/刷新 community_<id> session
        -> 调用既有居住证只读接口
```

任务社区不在选中范围时停留在本地错误状态；系统不会用其它社区账号绕过范围限制。

## 测试与验证

后端测试覆盖多社区保存、规范化、空范围、非法 ID、重复 ID、不存在/停用/未配置社区、旧单社区兼容、社区账号和 session 隔离、范围外不发请求、身份不匹配和敏感信息不泄露。前端测试覆盖多选渲染、可选状态、数组提交、服务端规范化结果、旧响应兼容、错误提示和窄屏布局。

提交前运行相关 pytest、前端测试、Python 编译、生产构建、`git diff --check` 和敏感信息扫描。本机没有真实 MySQL、居住证平台或生产运行环境，真实数据库、外部平台、公网手机和设备验收不在本 PR 验证范围内。

## 回滚与发布边界

回滚只恢复本次程序和系统配置代码，不删除业务数据、不恢复外部写入，也不执行数据库迁移。PR 不代表生产部署、真实账号测试、外部平台验收或版本发布；这些动作需要单独的受控流程和明确授权。
