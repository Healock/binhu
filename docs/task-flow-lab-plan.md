# “我的任务流”实施计划

## 目标

“我的任务流”不是另一套待办数据库，而是现有业务任务的个人编排视图。它要让用户在等待外部人员、系统同步或后台任务时，仍能看到可以并行推进的下一步，避免把所有业务都做成严格串行流程。

## 第一阶段：超级管理员内测

当前实现范围：

- 仅超级管理员可见 `/task-flow-lab` 和导航入口。
- 复用五类流口任务的筛选、列表和详情接口，不新增数据库表。
- 超级管理员选择核查人后，聚合其未完成任务；每类最多读取100条，并明确提示截断数量。
- 任务按三类展示：
  - 现在可做：可以直接进入详情继续核查。
  - 等待协作：等待研判或其他岗位处理。
  - 需要关注：来源重复、冲突或待腾讯同步。
- 节点支持拖动、缩放、画布平移、搜索、自动整理和手工虚线连接。
- 节点双击或点击按钮进入原任务详情；任务保存、权限和腾讯写回全部沿用原逻辑。
- 页面每30秒被动刷新。自动刷新不携带用户活动标记，不能延长会话。
- 节点位置和虚线仅保存在当前浏览器；不保存姓名、地址等任务正文。
- 手机端使用紧凑任务列表，不强行呈现无限画布。

第一阶段明确不做：

- 不允许画布连线修改真实任务依赖。
- 不新增通用工作流执行引擎。
- 不聚合下发、调照片、工单、辖区档案和后台任务。
- 不向组长、组员或其他岗位开放入口。
- 不实现多人共享画布或服务器端布局同步。

## 第二阶段：本人任务闭环

- 新增统一的任务流聚合接口，由后端根据当前账号和具体业务权限返回任务引用。
- 组员默认只看本人；组长同时拥有本人视角和本社区统筹视角；上级岗位继续按职责范围过滤。
- 组长分配任务后生成安全任务变化事件，正在打开沙盒的网格员通过服务器单向推送立即看到节点；定时刷新继续作为断线兜底。
- 增加“新任务收件箱、今天可做、等待他人、等待系统、即将到期”分区。
- 从详情返回时恢复原画布视口、选中节点和筛选条件。
- 布局按账号保存到平台，只保存内部任务引用、坐标、折叠状态和用户虚线，不保存业务正文。

## 第三阶段：跨模块编排

- 接入下发任务、网格研判、调照片工单、通用工单、辖区档案问题以及导入、同步、发布等后台任务。
- 引入只读的系统依赖边：实线代表业务真实依赖，用户不能随意删除或改向。
- 用户虚线继续只表达个人计划、备注和处理顺序，不改变真实业务流程。
- 支持任务组和折叠节点，避免一次分配几十条后铺满画布。
- 系统识别“等待期间仍可处理”的动作，并在节点上直接提示推荐下一步。

## 第四阶段：模板与复盘

- 为常见业务建立只读流程模板和自动布局。
- 支持按人员、社区、批次和时间回放任务状态变化。
- 提供等待时间、实际处理时间和阻塞原因统计，但不建立实名工作量排名。
- 经过权限和审计设计后，再评估共享协作画布和管理员流程配置能力。

## 数据和安全边界

- 真实任务仍以各业务模块原表和现有接口为唯一来源。
- 沙盒不能绕过详情接口、来源版本、行哈希、权限范围或腾讯回写开关。
- 前端隐藏不是权限控制；开放给其他岗位前必须增加后端聚合接口并执行数据范围过滤。
- 普通日志、操作记录和任务流布局不能保存身份证号、手机号、地址、研判正文或附件内容。
- 系统依赖边与用户虚线必须在数据模型和视觉上明确区分。

## 第一阶段验收标准

- 管理员和普通账号无法通过导航或直接地址进入内测页。
- 超级管理员可以选择核查人并看到其五类未完成任务。
- 新分配任务在刷新周期内出现，完成或改派任务在刷新周期内离开当前沙盒。
- 点击任务进入正确详情，返回后画布位置不被自动重排。
- 用户拖动和连线不会修改业务数据。
- 自动刷新不延长登录会话。
- 桌面端画布、深浅色模式和手机列表均可正常使用。
