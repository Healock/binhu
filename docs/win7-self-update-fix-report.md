# Windows 7 自更新安装失败修复报告

报告日期：2026-08-25

## 问题现象

Windows 7 客户端可以发现并下载更新，但在 Velopack 应用更新、准备重新启动客户端时，VxKex Loader 弹出：

```text
CreateProcess 失败：拒绝访问。
```

## 原因

Velopack 安装完新版本后，会在更新程序自身完全退出前重新启动客户端主入口。Windows 7 版主入口随后立即通过 VxKex Loader 启动新版 Electron。此时更新程序、文件系统过滤驱动或安全软件仍可能短暂占用刚替换的可执行文件，VxKex 的进程创建因此收到拒绝访问。

普通用户从桌面快捷方式启动客户端时不存在这段时序竞争。

## 修复

- Electron 调用 Velopack 时向更新后的重启入口传入专用参数 `--binhu-after-update`。
- Win7 原生启动器仅在收到该参数时读取父进程并等待父更新进程退出，最长等待 30 秒。
- 父进程退出后额外等待 500 毫秒，再通过 VxKex 启动新版 Electron。
- 普通启动不等待，不改变日常打开速度。
- 增加 JavaScript 回归测试和桌面架构检查，防止后续移除更新标记或等待逻辑。

## 验证范围

- Win7 启动器已使用 Windows C++ 工具链成功编译。
- Electron 更新控制器测试已验证 Velopack 收到重启标记。
- 桌面架构检查已验证启动器包含更新等待逻辑。

真实 Windows 7 的跨版本升级仍需在 `0.26.2 -> 0.26.3` 发布后完成最终验收，并确认版本、登录状态和快捷方式均正常。
