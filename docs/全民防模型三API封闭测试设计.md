# 全民防“疑似未注销模型三”API 封闭测试设计

> 状态：v0.21.0 开发分支已实现单条真实登记代码与虚构数据测试；尚未执行真实登记、合并、部署或创建标签
> 最后更新：2026-08-16
> 现行路线：优先验证旧平台 API；Redroid/Appium 仅作为历史备选方案

## 1. 文档用途

这份文档是后续开发、复审和测试的唯一现行入口，记录已经确认的事实、产品决定、安全边界和仍未确认的问题。后续开发人员不得只依据聊天记录、接口名称或旧自动化计划实现登记。

仓库不得保存以下材料：

- 旧平台账号密码、登录令牌或会话材料；
- 真实姓名、身份证号、手机号、地址或照片正文；
- APK、PCAP、原始请求响应、真实测试名单；
- Android IMEI、Android ID 等真实设备标识。

这些原始证据只保存在项目管理人控制的非 Git 目录中。本文只记录经过核验的结构和结论。

## 2. 当前产品决定

### 2.1 账号和权限

- 测试能力只允许平台登录账号 `shenshenghua` 使用。
- 后端必须按当前登录账号精确校验，不能只依靠前端隐藏菜单。
- 管理员、超级管理员或拥有相邻权限的其他账号也不能绕过该白名单。
- 白名单不得由请求参数传入；应使用服务端配置，默认值固定为 `shenshenghua`，生产不得扩展为角色或权限组。
- API 测试总开关默认关闭。只有“总开关开启 + 当前账号命中白名单”时，测试接口才可访问。
- 登录旧平台所需凭据可以由服务器密钥注入，也可以通过受限的全民防设置页录入；设置页保存时加密写入 `_system_config`，密码不回显。凭据不得进入普通系统配置响应、日志、审计正文、前端错误信息或 Git。

### 2.2 第一阶段业务范围

- 只支持“疑似未注销模型三”的单条测试。
- 第一阶段只支持核查结果“在吴”，抓包中对应 `hcjg=2`、`type=3`。
- “近期返吴”“离吴”及其他核查结果暂不实现，不能根据字段名称猜测枚举值。
- 不做批量登记、不做定时任务、不自动扫描待办、不开放给普通业务用户。
- 不提供通用请求转发器、任意接口调用器或可编辑的原始请求体。
- 真实登记只允许从一条具体任务重新预演后进入，必须输入“确认登记”并完成二次确认。
- 真实登记和写入协议确认使用独立开关，默认关闭；开关持续开启也不会产生自动、批量或定时执行。

### 2.3 照片规则

- “从居住证获取照片”是“在吴”登记链路的必经步骤。
- 业务反馈表明，即使页面起初未显示照片，也可以通过该按钮取得照片。
- 程序仍必须验证返回内容是当前对象的有效图片；获取失败、身份不一致或图片无效时立即停止。
- 不允许跳过照片步骤、使用占位图、沿用上一人的照片或用其他来源照片猜测替代。

## 3. 已核验的证据范围

### 3.1 APK 静态分析

APK 是原生 Android 应用，包含 Retrofit/OkHttp 以及以下模型三相关页面和接口定义：

- `EnergizeUncheckListFragment`
- `EnergizeUnRegisteredListFragment`
- `EnergizeSubmitPage`
- `RetrofitService`

APK 使用独立的 `/grid_terminal_interface/` 接口体系，不应与旧网页的 `/api/masses/*` 接口混为一谈。

### 3.2 单条成功抓包

已经核验一条由旧 Android 客户端完成的“在吴 + 从居住证取得照片 + 登记 + 模型三反馈”成功链路：

1. 查询未处理和相关状态任务；
2. 按身份证查询人员信息；
3. 从居住证系统查询本地照片；
4. 执行登记前检查；
5. 上传照片正文；
6. 保存居住证照片关联；
7. 新增或更新人员登记信息；
8. 反馈模型三核查结果；
9. 再次查询确认任务不再处于原待处理状态。

抓包内共有 15 个成对 HTTP 事务，业务写接口均返回 HTTP 200 和业务成功码。该证据只证明当前 APK 版本、当前账号和“在吴”结果下的单条链路，不代表其他结果或批量调用已经确认。

### 3.3 辖区编码口径

生产单条只读验证和既有成功抓包共同确认：模型三任务字段 `xfsq` 是 12 位组织/下发辖区编码，`PersonnelInfo.communityCode` 是 10 位人员社区编码。两者属于不同编码体系，不能直接等值比较。

只读预演继续把以下条件作为硬校验：登录机构属于滨湖新城派出所、上游任务派出所属于滨湖新城派出所、身份证号和姓名一致、上游任务唯一。两个社区编码只返回到受限预演页面供人工核对，不因位数或值不同阻断照片读取。

## 4. 已确认的接口顺序

以下均以旧平台网关的 `/grid_terminal_interface/` 为前缀；主机地址不得硬编码进仓库。

| 顺序 | 方法 | 路径 | 用途 | 第一阶段性质 |
|---|---|---|---|---|
| 1 | POST | `fnmx/queryYysList` | 查询模型三任务及处理状态 | 只读 |
| 2 | POST | `enterHouse/queryPeopleBySfzh` | 查询人员现有信息 | 只读 |
| 3 | GET | `jzz/queryLocalPhoto` | 从居住证取得照片 | 只读 |
| 4 | POST | `enterHouse/checkCk` | 登记前检查 | 只读校验 |
| 5 | POST | `masses/uploadPhoto` | 上传照片正文 | 写入 |
| 6 | POST | `jzz/saveLocalPhoto` | 保存照片关联 | 写入 |
| 7 | POST | `enterHouse/addPeople` | 保存人员登记信息 | 写入 |
| 8 | POST | `fnmx/fnmxCheck` | 反馈模型三核查结果 | 写入 |
| 9 | POST | `fnmx/queryYysList` | 写后状态复核 | 只读 |

不得改变写入顺序，也不得把 HTTP 200 直接视为业务成功。每一步都要校验业务返回码和必要的返回字段。

## 5. 关键请求字段

### 5.1 `fnmx/queryYysList`

已观察到的表单字段：

```text
cljg, dz, endTime, hcjg, lxfs, mjjh, pageNum, pageSize,
pcsbm, sfzh, source, startTime, xm
```

测试查询必须使用精确身份证条件并限制最小分页，不得用宽泛条件枚举其他派出所数据。查询结果必须再次校验派出所和目标身份。

### 5.2 `queryPeopleBySfzh` 和 `checkCk`

```text
sfzh, source
```

其中 `source=android` 已在抓包和 APK 行为中确认。

### 5.3 `masses/uploadPhoto`

已观察到 JSON 字段：

```text
csrq, jmzh, sfbljzz, sqdm, txsj, xb, xm
```

`txsj` 为 JPEG 的 Base64 正文。程序必须在内存中处理并限制大小，不写普通日志或审计，不长期落盘。

### 5.4 `jzz/saveLocalPhoto`

已确认核心语义：

- 身份证号；
- `imageType=3`；
- `label=2`；
- 当前操作人；
- 不上传文件正文。

该请求采用表单/多段格式，开发时必须根据抓包重新构造并用虚构数据进行序列化测试，不能仅凭字段名称改变编码方式。

### 5.5 `enterHouse/addPeople`

人员对象字段很多。第一阶段必须采用“查询返回对象为基础，按 APK 确认的规则补充或转换”的方式，禁止手工拼一个精简对象。

已确认的特殊规则：

- 原查询对象中的既有业务值不得被清空；
- 一批查询为空的可选字段在提交时转换为空字符串；
- `csrq` 可从身份证号推导，但必须与查询结果交叉校验；
- `djrq` 使用实际登记业务日期；
- `sfbljzz=1`；
- `operateType=2`；
- `fromPersonCheck=true`；
- `canEdit=false`；
- `beizhu` 会被 APK 页面覆盖为当前旧平台登录人的姓名，而不是保留查询返回值；
- `operateBy` 来自当前旧平台登录账号；
- `sbsbh` 来自 Android 运行时设备标识。

已确认有少量查询专用字段在提交时省略，也有提交专用字段新增。正式开发前应把脱敏字段差异固化为自动化契约测试，防止前端 DTO 或旧平台字段变化导致静默覆盖。

### 5.6 `fnmx/fnmxCheck`

已观察到字段：

```text
communityCode, hcczr, hcjg, logoutReason, personID,
qwdxz, qwdxzqh, sbsbh, source, type, xfid
```

当前只确认“在吴”：

```text
hcjg=2
type=3
source=android
```

`personID`、`xfid`、操作人和设备标识必须来自本次查询/登录上下文，不能从另一条任务复用。

## 6. 登录信息和动态字段来源

APK 静态代码已经确认：

- 登录请求使用用户名、密码，并附带 `IMEI` 和 `MACHINEUID`；
- 登录成功后，账号输入值被保存为 `WpaUserData.userID`；
- 模型三 HTTP 的 `mjjh` 直接取 `WpaUserData.userID`，不是 `MID_LOCAL.MJJH`；
- `MID_LOCAL/QID_D_LOCAL` 返回的 `MJJH`、`MJXM`、`JGBM`、`JGMC` 只刷新工作身份参数；
- 登录响应参数表被整体保存，`JGBM` 等机构字段通过 `getDataByName` 动态读取；
- `hcczr`、`operateBy` 和模型三 `mjjh` 使用当前登录态的 `userID`；
- `beizhu` 使用当前登录态的操作人姓名；
- 机构代码从登录响应动态取得，不应硬编码。

静态分析还原的登录传输合同为：

- 独立 TCP 连接，不使用 HTTP，也没有额外长度前缀；
- 请求是无 XML 声明、GB2312 兼容字节的 XML，根节点为 `message`，模块为 `base`；
- `login` 节点包含账号、密码、`platform=Android` 和 `violent=true`；
- `IMEI`、`MACHINEUID` 作为登录参数发送；
- 客户端读取到 `</message>` 为止，并严格校验响应序号、模块和响应类型；`errcode` 缺失或为 `0` 都表示协议层通过，非零才失败；
- 登录后必须依次完成时间同步和 `MID_LOCAL/QID_D_LOCAL`，再进入只读 HTTP；
- `MID_LOCAL` 的工作身份字段与登录账号 `userID` 分开保存，不能相互替代。

登录主机、端口、账号、密码和设备标识从生产密钥或全民防专用设置页读取。设置页只允许超级管理员访问；密码写入后不回显，IMEI 和 MACHINEUID 按项目管理人要求完整显示。应用加密密钥仍只存在服务器私密配置中，不能在普通系统设置接口返回。开启 `QMF_LOGIN_PROTOCOL_VERIFIED` 前仍必须完成授权设备和单条只读实测，不能用设置页录入本身代替协议核验。

因此首期应在每次测试会话登录后动态取得并校验：

- 账号标识；
- 操作人姓名；
- 机构代码和机构名称；
- 登录可用状态。

在任何读取或写入前，必须确认机构属于“滨湖新城派出所”。机构不符、字段缺失或登录响应结构变化时立即停止。

### 6.1 设备标识例外

APK 的 `MACHINEUID` 行为是：

1. 读取 `Build.MANUFACTURER`；
2. 拼接一个空格；
3. 再读取 `Build.MODEL`。

`IMEI` 的最终生成或持久化来源仍未从 APK 侧完整确认。两者都不是账号资料，服务器不能随机生成、伪造或用自身主机属性替代。第一阶段只能使用经授权的专用设备值作为受保护配置；`MACHINEUID` 必须与授权设备的厂商/型号组合一致。

### 6.2 TCP 会话边界

- APK 在 HTTP 读取期间保持登录 TCP 连接，并大约每 60 秒发送一次心跳；
- 当前只读预演在会话内依次完成登录、时间同步、`MID_LOCAL/QID_D_LOCAL` 和四个白名单 HTTP 请求；
- 服务端是否强制要求 TCP 在线、是否按来源 IP 或会话状态校验 HTTP，仍未得到服务端契约确认；
- 未确认的心跳帧、错误码目录、会话过期和并发规则不能靠猜测补造。预演遇到连接中断、未知响应或结构变化时必须失败即停。

## 7. 封闭测试设计

### 7.1 当前两阶段模式

**只读预演模式**：

- 登录旧平台并动态读取操作人和机构信息；
- 精确查询一条模型三任务；
- 查询人员信息；
- 从居住证取得照片并只校验格式、大小和身份关联；
- 生成预计写入步骤和字段差异摘要；
- 不调用四个写接口。

**单条真实登记模式**：

- 只有超级管理员同时开启真实登记并确认写入协议后才可准备；
- 仍只允许 `shenshenghua`；
- 每次只接受一个已经从滨湖平台任务详情选定的来源任务；
- 每条必须重新执行完整只读链路，生成十分钟有效且只能执行一次的准备记录；
- 提交前输入固定短语“确认登记”并通过二次确认；
- 写客户端只实现四个固定接口，并严格执行九步顺序；
- 运行成功、失败或不确定后均不能从头重放；腾讯备注标记失败只能单独重试标记。

### 7.2 服务端强制条件

每次请求必须同时满足：

1. 只读总开关、真实登记开关、登录协议确认和写入协议确认均已开启；
2. 当前平台账号精确等于 `shenshenghua`；
3. 请求来自正常登录会话并通过 CSRF/同源校验；
4. 业务类型为疑似未注销模型三；
5. 核查结果为“在吴”；
6. 当前平台来源仍唯一，来源行 ID、版本和摘要在上游读取前后均一致；
7. 旧平台登录机构为滨湖新城派出所；
8. 居住证照片成功取得并通过校验；
9. 当前没有另一条登记在执行；
10. 与上一条预演之间已经超过冷却时间；
11. 数据库中没有另一条执行中的运行；
12. 当前任务、上游任务或安全幂等键不存在既往执行尝试。

前端按钮隐藏只是辅助体验，不能代替以上后端校验。

### 7.3 准备、执行与失败处理

- 浏览器只提交业务类型、平台行键、来源行 ID 和期望版本，不提交身份证号。
- 后端从最新来源行读取身份证号，并在访问上游前、返回敏感资料前各校验一次来源版本和摘要。
- 单进程内同一时间只允许一条预演，并设置短暂冷却；真实执行领取另外使用数据库级串行锁，页面不提供多选、批量或自动重试。
- 上游超时、非成功 HTTP 状态、业务错误、空响应、重复任务、人员不一致、机构不符或图片无效全部安全失败。
- 图片仅以当前认证响应的 Base64 返回并保存在浏览器内存，关闭窗口后不写平台附件、数据库或磁盘。

- 单条任务使用平台任务定位摘要、来源版本/摘要和旧平台任务 HMAC 组成安全幂等键，运行表不保存原始业务主键或身份证号。
- 执行前再次查询当前状态，已经处理的不再写入。
- 每次外部调用前先把步骤保存为 `sending`，明确成功后改为 `succeeded`；服务重启会把遗留发送中步骤和执行中运行转为不确定。
- 写请求发生超时、连接中断或响应无法判断时，标记“结果不确定”，停止后续步骤且禁止自动重试。
- 明确业务错误同样停止并冻结；如果此前已有写步骤成功，整次运行按不确定处理。
- 在能够通过人工核对确认外部状态前，不允许用户再次提交；当前版本不提供解冻或重放接口。
- `fnmxCheck` 成功后必须重新执行 `queryYysList`，确认该任务已从原待处理集合消失或进入预期状态。
- 最终复核成功后才向腾讯备注追加固定标记；标记失败不改变全民防成功状态，也不能触发全民防重放。

### 7.4 界面限制

- 不加入普通菜单和手机 Dock。
- 不提供列表、多选、全选、导入、批量、计划任务或自动重试。
- 只允许从一条具体模型三任务进入测试页。
- 页面把“只读预演”和“真实登记”分为两个明确入口；真实登记只有完成本次准备后才显示确认输入框。
- 准备窗口显示完整人工核对资料、照片、预计字段变化、九步顺序和不可撤销提示。
- 执行期间显示九步状态，关闭页面后可从同一任务详情恢复进度；运行记录不恢复照片正文。
- 普通任务查看者只看到最终“全民防已反馈”和完成时间，不接收私有步骤或失败原因。

## 8. 日志和证据

允许记录：

- 平台任务内部 ID；
- 外部 `xfid` 的 HMAC 或安全摘要；
- 执行步骤名称、开始/结束时间、HTTP 状态和业务返回码；
- 字段名称集合和字段差异数量；
- 登录机构校验结果；
- 图片格式、字节数和 SHA-256；
- 最终状态和是否需要人工复核。

禁止记录：

- 旧平台密码、设备标识正文、令牌或完整请求头；
- 姓名、身份证号、手机号、地址；
- 图片 Base64 或照片文件；
- `addPeople` 完整请求或响应正文；
- 可以直接重放写入的原始请求材料。

真实测试结束后应生成一份安全摘要，保留每一步是否成功以及写后查询证据，不保留敏感正文。

## 9. 失败处理

| 失败点 | 处理方式 |
|---|---|
| 登录失败或机构不符 | 停止，不查询业务数据 |
| 查询不到唯一任务 | 停止，人工核对 |
| 人员信息缺失或身份不一致 | 停止，人工核对 |
| 居住证照片无效 | 停止，不调用写接口 |
| `checkCk` 不通过 | 停止，展示安全错误摘要 |
| 照片上传结果不确定 | 停止，禁止自动重试 |
| 照片关联失败 | 保留步骤状态，人工确认后处理 |
| `addPeople` 结果不确定 | 停止，不调用 `fnmxCheck` |
| `fnmxCheck` 失败 | 不把平台任务标为登记成功 |
| 写后查询不一致 | 标记需要人工复核，不自动重放 |

## 10. 仍未确认的问题

- 登录 TCP 主机和端口已经由 `task-c` 抓包确认，但生产服务器网络是否可达、来源 IP 是否被允许仍未确认；
- 登录 XML 消息边界、编码、时间同步、`MID_LOCAL/QID_D_LOCAL` 顺序和客户端重连代码已经由抓包与 APK 静态分析确认；服务端正式错误码目录、超时合同、断线处置和未知心跳帧格式仍未确认；
- 专用设备标识的合规存放、访问责任人、轮换方式和长期稳定性仍未确认；`MACHINEUID` 的生成规则已确认，但登录 `IMEI` 的最终来源和跨设备变化规则仍未知；
- 旧平台会话是否存在服务端并发登录限制、顶号行为、有效期、主动撤销规则，以及 HTTP 是否强制依赖 TCP 在线仍未确认；
- 来源 IP、调用频率、时间窗口、授权期限和撤销方式没有旧平台系统管理方提供正式合同；
- 同一人员已经登记、已经反馈或跨社区重复任务的完整业务返回分类；
- “近期返吴”“离吴”等其他结果的真实枚举、必填字段和成功链路；
- 旧平台字段或 APK 版本升级后的兼容检测方式；
- 是否存在正式、受支持的服务端集成凭据或接口文档；
- 生产服务器完成一次授权的单条只读登录和查询验证，并确认没有调用写接口；设置页录入凭据只解决配置入口，不代表旧平台已经授予正式服务端集成授权。

由于目前没有可联系的旧平台系统管理方，以上服务端事实不能用 APK 字符串、单次成功样本或经验值补造。设置页可以让项目管理人完成受控配置，但不能替代旧平台授权合同。在这些问题确认前，不得扩大业务结果、账号范围或执行规模；生产开关继续保持关闭。
