## 重点业务链路

### 流动人口管理：人员登记、注销（动态确认）

页面入口为“流动人口管理 → 人员登记、注销”。点击“查询”后，前端按顺序执行以下只读请求：

1. `POST /szjzz/searchIsck`
   - 用途：检查查询对象是否属于常住人口，决定是否继续流动人口预检索。
   - 请求正文：`sfzh`（公民身份号码）、`xzqh`（当前登录机构代码前 6 位）。
2. `POST /szjzz/searchzzrk`
   - 用途：按公民身份号码读取居住证平台中的流动人口登记资料。
   - 请求正文：`sfzh`、`xzqh`。

完整接口地址以 `/grandlynn-boot` 为基路径，请求需要登录后动态取得的 `X-Access-Token`，并携带平台公共租户头。`xzqh` 应从本次登录账号所属机构代码动态取得，不能固定成某个社区代码。

2026-08-26 已在受控环境完成两类只读样本验证：

- 有登记资料：`searchIsck` 可以返回无常住人口记录，随后 `searchzzrk` 返回 `success=true`、`code=200` 和人员登记对象。
- 无登记资料：`searchIsck` 返回 `success=true`、`code=200`、`result=null`；随后 `searchzzrk` 返回 HTTP 200，业务 `success=false`、`code=500`、`message=操作失败，没有查询到数据`、`result=null`。

其中第二种是该接口明确的“没有流动人口登记资料”业务结果，不应归类为 HTTP 故障。平台在同时满足 HTTP 200、`code=500`、明确的无数据消息且 `result=null` 时，可将对应流动人口核查指令标记为“首次登记”。超时、HTTP 4xx/5xx、登录失效、响应无法解析或其他业务错误不得标记为“首次登记”。

本链路只用于查询和业务标记，不调用人员登记、注销、照片上传或其他写接口。

1. 使用明确授权的测试对象，从当前账号真实页面操作中只读采集 Network 请求，把重点业务接口的 `UNKNOWN` 方法和候选字段升级为动态证据。
