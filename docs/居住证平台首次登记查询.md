# 居住证平台首次登记查询

## 用途

平台对手机任务工作台中的每条流动人口核查指令，按任务当前身份证号只读查询居住证平台“流动人口管理 → 人员登记、注销”。只有居住证平台明确返回“没有查询到数据”时，任务卡片、Table 和详情才显示 `首次登记`。

该标签只是登记资料提示，不改变任务核查结果、完成状态或腾讯来源数据，也不会向居住证平台提交登记、注销、人员保存或照片写入。

## 已确认接口

接口基地址、账号、密码、MAC 服务地址、机构代码和登录令牌由超级管理员在系统设置中配置。真实地址和凭据不进入 Git、普通日志或审计。

登录链路：

```text
GET  /sys/randomImage/{毫秒时间戳}
POST /sys/login
```

人员查询链路：

```text
POST /szjzz/searchIsck
POST /szjzz/searchzzrk
```

两个人员查询接口的 JSON 请求均为：

```json
{
  "sfzh": "任务中的身份证号",
  "xzqh": "登录机构代码前六位"
}
```

请求使用登录返回的 `X-Access-Token`，并固定携带 `tenant_id: 0`。`searchIsck` 用于常住人口预检索，`searchzzrk` 用于查询流动人口登记资料。

## “首次登记”的严格判定

2026-08-26 的授权只读实测确认：居住证平台“查不到流动人口登记资料”并不使用外层 HTTP 500，而是外层 HTTP 200，业务 JSON 同时符合：

```text
success = false
code = 500
message 包含“没有查询到数据”
result = null
```

只有四项同时成立才标记 `首次登记`。下列情况统一显示“居住证查询待核对”，不得误标：

- 真正的 HTTP 失败；
- 请求超时或连接失败；
- 登录令牌失效；
- `code=500` 但消息不是“没有查询到数据”；
- `result` 不是空值；
- JSON 无法解析或响应字段发生变化。

当 `success=true、code=200` 且 `result` 是登记对象时，状态为“居住证已有登记”。平台不保存或返回该登记对象正文。

## 平台实现边界

- 后台以两路并发持续处理待查询任务，单批最多 50 条，直到本轮队列处理完毕。
- 身份证发生变化或查询结果超过 7 天时重新查询。
- 服务重启中断的只读任务会恢复为待查询。
- `_residence_registration_status` 只保存任务定位、身份证 HMAC 摘要、状态、安全错误码和时间，不保存姓名、身份证明文、手机号、地址或外部响应正文。
- 外部路径使用固定只读白名单，不提供任意路径转发能力。

## 平台管理接口

以下接口仅供超级管理员设置和触发只读查询：

```text
GET  /api/residence-platform/config
PUT  /api/residence-platform/config
POST /api/residence-platform/captcha
POST /api/residence-platform/login
POST /api/residence-platform/scan
```

配置中的账号、密码和访问令牌加密保存；密码和令牌只返回“是否已配置”，不向浏览器回显原值。
