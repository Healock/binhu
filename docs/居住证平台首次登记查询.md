# 居住证平台首次登记查询

## 用途

平台对手机任务工作台中的每条流动人口核查指令，按任务当前身份证号只读查询居住证平台“流动人口管理 → 人员登记、注销”。只有居住证平台明确返回“没有查询到数据”时，任务卡片、Table 和详情才显示 `首次登记`。

该标签只是登记资料提示，不改变任务核查结果、完成状态或腾讯来源数据，也不会向居住证平台提交登记、注销、人员保存或照片写入。

## 已确认接口

接口基地址、统一密码和 MAC 服务地址由超级管理员在系统设置中配置。每个社区的账号由社区管理中的 10 位全民防社区代码末尾追加 `00` 自动生成；社区令牌分别加密缓存。真实地址和凭据不进入 Git、普通日志或审计。

登录链路：

```text
GET  /sys/randomImage/{毫秒时间戳}
POST /sys/login
```

人员查询链路：

```text
POST /szjzz/searchIsck
POST /szjzz/searchzzrk
```

任务详情在最近一次状态为“居住证已有登记”时，还会按需调用：

```text
POST /szjzz/searchPhoto
```

请求 JSON 只包含任务来源中重新读取的身份证号：

```json
{
  "sfzh": "任务中的身份证号"
}
```

成功响应的 `result["图象数据"]` 为 Base64 图片。平台只接受 5MB 以内且文件头确认为 JPEG 或 PNG 的图片，并仅在当前详情响应中以内存 Data URL 返回；图片、人员资料和外部完整响应均不写入数据库、磁盘、日志或审计。

两个人员查询接口的 JSON 请求均为：

```json
{
  "sfzh": "任务中的身份证号",
  "xzqh": "登录机构代码前六位"
}
```

请求使用登录返回的 `X-Access-Token`，并固定携带 `tenant_id: 0`。`searchIsck` 用于常住人口预检索，`searchzzrk` 用于查询流动人口登记资料。

## “首次登记”的严格判定

2026-08-26 的授权只读实测确认：居住证平台“查不到流动人口登记资料”并不使用外层 HTTP 500，而是外层 HTTP 200，业务 JSON 同时符合：

```text
success = false
code = 500
message 包含“没有查询到数据”
result = null
```

只有四项同时成立才标记 `首次登记`。下列情况统一显示“居住证查询待核对”，不得误标：

- 真正的 HTTP 失败；
- 请求超时或连接失败；
- 登录令牌失效；
- `code=500` 但消息不是“没有查询到数据”；
- `result` 不是空值；
- JSON 无法解析或响应字段发生变化。

当 `success=true、code=200` 且 `result` 是登记对象时，状态为“居住证已有登记”。后台状态扫描仍然不保存或返回该登记对象正文；用户打开有权查看的任务详情时，页面另行实时读取一次，并仅投影以下核对字段：

- 系统登记住址：`jlx_dictText + mph`；
- 年龄及出生日期：优先使用 `birth`，字段无效时从已完整校验的身份证号提取，年龄按查看当天计算；
- 户籍地址：`hjdz` 对应的行政区划中文全名加 `hjdzxz`，代码无法解析时保留六位代码；
- 民族：将 `nation` 按国家民族代码翻译为中文；
- 注销状态：`rysfzx=0` 为“未注销”，`rysfzx=1` 为“已注销”，其他值显示“状态待核对”；
- 资料更新时间：`rygxsj`；
- 照片：来自独立的 `searchPhoto` 只读接口。

详情接口不接受浏览器提交身份证号，而是再次通过任务定位和当前用户社区范围读取服务器来源行。来源不唯一、跨社区、状态不是“已有登记”或人员资料实时查询已变化时安全终止；详情局部失败不影响任务其他内容。

## 平台实现边界

- 保存并开启完整配置后，后台立即执行一次全量查询；此后默认每 30 分钟重新查询全部流口指令核查对象，间隔可由超级管理员在系统设置中调整（5 至 1440 分钟）。超级管理员也可点击“重新查询全部任务”立即强制刷新。
- 后台以两路并发持续处理待查询任务，单批最多 50 条，直到本轮队列处理完毕。
- 每轮开始时以当时全部流口指令核查任务为准重新排队，历史成功结果也会刷新；一轮尚未结束时不会并行叠加下一轮。
- 服务重启中断的只读任务会恢复为待查询。
- 单条查询依次调用 `searchIsck` 和 `searchzzrk`。平台记录本次总耗时（毫秒）并在状态提示中显示，不记录各接口正文或人员信息。
- `_residence_registration_status` 只保存任务定位、身份证 HMAC 摘要、状态、安全错误码、查询总耗时和时间，不保存姓名、身份证明文、手机号、地址或外部响应正文。
- 外部路径使用固定只读白名单，只包含 `searchIsck`、`searchzzrk` 和 `searchPhoto`，不提供任意路径转发能力。

## 登录和社区账号规则

- 居住证网页加载登录页时会请求 `/sys/randomImage/{checkKey}`，但页面不显示验证码输入框；登录请求使用该 `checkKey` 并提交空字符串 `captcha`。平台复刻这一已确认行为，挑战获取和登录均在后台完成。
- 平台从任务来源社区匹配社区管理中的正式社区或别名，再以 `全民防社区代码 + 00` 生成账号。统一密码只加密保存一份，不逐社区配置或回显。
- 每个社区分别缓存登录令牌。查询参数 `xzqh` 优先使用该社区账号登录响应中的机构代码；响应未提供时使用全民防社区代码前六位。
- 仍需通过生产运行观察全部社区账号是否均能登录、令牌实际寿命以及不同社区的典型查询耗时；失败只记录安全错误码，不泄露登录响应正文。

## 平台管理接口

以下接口仅供超级管理员设置和触发只读查询：

```text
GET  /api/residence-platform/config
PUT  /api/residence-platform/config
POST /api/residence-platform/scan
GET  /api/mobile-tasks/{parser_type}/{row_key}/residence-detail
```

配置中的统一密码和社区访问令牌加密保存；密码和令牌只返回配置数量和状态，不向浏览器回显原值。
